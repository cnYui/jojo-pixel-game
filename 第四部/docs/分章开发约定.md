# 第四部分章开发约定

用户（LQM）2026-11-03 要求把第四部《不灭钻石》整部做完，按章各开一个线程：每章一个剧情玩法线程、一个背景线程。几十条分支同时改同一个 `第四部/` 目录，这份约定的目的只有一个：每章只改自己的文件，合并时不打架。

设计文档（Claude Doc）：https://claude.ai/artifact/1wH9fViMTRBgfL8HaeUz1r 。第二节 2.1 是 13 段总表，2.2 是每段谁能当队长，2.5 是全部战斗，第三节是角色和替身，后面按章写了节拍和战斗。分章详情目前写到第6章，第7章以后只有总表那一行，开工时照总表和原著补全开发脚本。

## 1. 分支和合并

- 所有线程从 `claude/project-thread-59mcgd` 开分支，PR 的 base 也选它（PR #3 还没合进 main）。PR #3 合进 main 以后改成从 main 开、base 选 main。
- 合并由 59mcgd 这条线（“设计 JoJo 第四部剧情游戏剧情”线程）做。合并顺序不限，冲突只该出在生成文件上（见第 7 节）。
- 不要往别人的分支推；不要改别章的文件。实在要改公共文件（引擎、`main.js`、`p4_common.js`、测试工具），单独一个小提交，PR 说明里写清楚，并告诉 59mcgd 线程。

## 2. 每章自己的文件

以第 N 章、章节 key `chN` 为例（终章 key 是 `final`，地图后缀 `_fin`；序章是 `prologue` / `_pro`）：

| 东西 | 位置 |
|---|---|
| 开发脚本（节拍、台词、战斗规则、素材清单、测试标记） | `第四部/docs/第N章_开发脚本.md`（格式照 `第2章_开发脚本.md` 和 `序章_开发脚本.md`） |
| 剧情节拍、地图、自由走动 | `第四部/游戏/story/p4_chN.js`（空壳已在 `index.html` 里占好位置） |
| 战斗和小游戏 | `第四部/游戏/story/p4_chN_fights.js`（同上） |
| 新角色 / 替身图集 | `第四部/tools/art/p4_chars_chN.py` → `assets/chars/<cid>.png`、`assets/heads/<cid>/…`，元数据写 `assets/_meta/chars_chN.json`（`chars`、`heroes`、`speakers`、`stands` 四块） |
| 新道具 | `第四部/tools/art/p4_props_chN.py` → `assets/props/<id>.png`，元数据写 `assets/_meta/props_chN.json` |
| 名牌、替身卡、地点卡、VS 卡的字 | 调 `p4_ui.namecard / standcard / location / vs_card` 画，再 `p4_ui.chapter_ui('chN', namecards={…}, …)` 写 `assets/_meta/ui_chN.json`。不要跑 `p4_ui.py` 的 main（它整份重画序章的 UI） |
| 背景（背景线程） | `第四部/tools/art/p4_bg_chN.py` → `assets/bg/<key>/…`，元数据 `assets/_meta/bg_chN.json`，每张图 `pack` 填 `chN`；锚点和开关层写 `第四部/docs/第N章_背景.md` |
| 试玩机器人的任务单和打法 | `第四部/tools/dev/p4_bot_chN.js`（`p4_play.js` 自动注入） |

`build_p4.py` 会把 `_meta/` 下的 `chars_*.json`、`props_*.json`、`ui_*.json`、`bg_*.json` 自动深合并进来，所以各章不用、也不要改 `chars.json`、`props.json`、`ui.json`、`bg.json`。篇章卡 13 张已经画好（`assets/ui/chapter/<key>.png`），开章时 `await S.chapterCard('chN')`。

不要碰的公共文件：`index.html`、`main.js`、`tools/art/p4_chars.py`（PR #6 在改仗助、康一、承太郎、疯狂钻石、朋子、良平、安杰罗这 7 个函数，新角色另起文件，用 `import p4_chars as C` 复用它的 `Sheet`、`save`、`recolor`、`frames`、`heads` 等）、`p4_props.py`、`p4_ui.py` 的表、`p4_bg.py` 和别章的 `p4_bg_chN.py`、别章的 story 文件。

## 3. 章节注册（story/p4_chN.js）

```js
'use strict';
(function () {
  const G = window.G, { base, walls } = G.p4Stage;   // 和序章同一套地图骨架（p4_stages.js）
  Object.assign(G.NAMES, { okuyasu: '亿泰' });        // 对话框短名，只加本章的新人
  G.STAGES.home_ch2 = base('home_ch2', 'hirose_living', 320, { obstacles: walls(10, 310, 320) });
  G.STORY.ch2 = async function (S) {
    await S.chapterCard('ch2');
    // …… 照开发脚本的节拍写；每个关键节点 S.mark('ch2_xxx')
  };
  G.STORY.ch2.marks = ['ch2_calendar', /* …整章应出现的标记 */ 'ch2_tbc'];   // p4_play.js 对照，缺了算没通过
  // G.STORY.ch2.packs = ['bg_ch3'];   // 可选：剧情中途换的背景不在本章地图上时，手动补包
})();
```

- 注册了 `G.STORY.chN`，标题的「选择章节」就能进这一章；没注册的章显示“制作中”。
- 地图 id 一律带本章后缀（`_chN` / `_fin`）。`playFrom` 会按这些地图用到的背景，把所在的背景包（包括别章的，比如 `bg_prologue`、`bg_ch2`）一起载入，借用别章背景不用复制。
- 每章开头按设计文档 2.2 自己组队；章与章之间不靠全局状态传东西（存档只记进度和发型记录）。
- 第四部的对白框平时在上方、战斗里在下方（`base` 已经设好 `dlgPos` / `dlgPosFight`），人站在画面最下面一条（可走带约 y 142–176，地面 150，画面高 180）。
- 剧情里不 await 的 `S.walk / S.arc / S.animate` 要接 `.catch(G.cancelIgnore)`，不然回标题时报错。
- 难度系数照设计文档 1.2：第1–4章 ×0.9，第5–7章 ×1.0，第8–10章 ×1.1，第11章到终章 ×1.2 → ×1.3。

## 4. 背景

- key、宽度、锚点、开关层由背景线程按设计文档该章“场景”定，写进 `第四部/docs/第N章_背景.md`；同章剧情线程照它用。剧情线程先开工的话，把开发脚本里的地图表发给背景线程对一下。
- 别章背景的变体（夜景、加一个路口、加脚手架）做成本章 pack 里的新 key：在自己的 `p4_bg_chN.py` 里 import 那一章的绘制函数，叠上新东西另存，不改别章的脚本。
- 背景图高 180、地面 150。实机核对：`node 第四部/tools/dev/p4_bgview.js --out 目录 --chapter chN`。招牌中文用文泉驿点阵正黑 12 px（WQY ttc index=1）。

## 6. 测试、录像、交付

- 整章测试：`node 第四部/tools/dev/p4_play.js --chapter chN --out 输出目录`。快进跑完整章，退出码 0 才算过：打完回到标题、没有报错、没有缺图缺字、没有连打拳声漏停、`G.STORY.chN.marks` 都出现了。最后一行会写没通过的原因，`report.json` 里有详情。序章的回归照旧不带 `--chapter`。
- 机器人：自由走动的任务单 `Object.assign(window.__bot.plan, { home_ch2: [{ id, go: [x, y], act: 'ok' | 'special' | 'swap', done: () => … }] })`；战斗打法 `window.__bot.fights['b03_thelock'] = (ctx, api) => { … }`，`api` 里有 `hold / tap / pulse / after / go / face / enemy / toHit / attackRhythm / note` 等（见 `p4_bot.js` 末尾）。机器人走的是和键盘同一条输入路径，它能打通 = 玩家照提示能打通。
- 连打拳声：`node 第四部/tools/dev/p4_rush_loop.js`（序章的水中项链战）；改了引擎的连打再跑。
- 录像（用户要求每个可玩版本都附游玩视频）：`node 第四部/tools/dev/p4_play.js --chapter chN --record 目录/第N章.webm --size 640x360 --read 1.2 --no-shots` 原生分辨率实录（直接录 1080p 会掉帧），再转 1080p：
  `ffmpeg -y -i 第N章.webm -vf "fps=60,scale=1920:1080:flags=neighbor" -c:v libx264 -preset slow -crf 18 -pix_fmt yuv420p -c:a aac -b:a 192k -movflags +faststart 第N章_1080p.mp4`
- 可玩包：`git archive --format=zip --prefix=jojo4_chN/ -o 包.zip HEAD:第四部/游戏`（双击 `index.html` 就能玩，「选择章节」进本章）。可玩包和录像放 `/mnt/project-files/jojo4/第N章/`。
- 发小红书、233乐园要用户点头，各章线程不要自己发。

## 7. 生成文件的冲突

这些文件是脚本整份生成的，合并冲突时不要手改，任取一边后重跑 `python3 第四部/tools/build_p4.py`：

## 8. 代码规矩

- 照仓库根 `AGENTS.md`：文档和注释用中文，注释写“为什么”。
- 台词照设计文档 1.3：新写、不冒充原作原句，每句 2 行内、不超过 56 字。
- 仓库里不带商业歌曲（标题曲用自写的芯片音乐 `title`）。用户指定的标题曲（2026-11-05 起是《Great Days》Break Down 1 分钟持续版）只在本地：`python3 第四部/tools/p4_title_song.py 源音频` 转成 `assets/audio/user/title_song.mp3`，再 `python3 第四部/tools/build_p4.py --no-font --include-user-audio` 打进 `游戏/data/music/title_song.js`，两样都被 `.gitignore` 排除。《Great Days》这版从 4.5 s 起是逐样本重复的 5.65 s 小节，所以转码时用 `--ss 0.44 --to 56.0 --loop-start 4.60 --loop-end 55.477369614512476`：前奏放一遍，之后只循环 9 个整周期，接缝处波形天然连着（引擎 `audio.js` 的 `loopPts` 认 `loopStart > 0`）。提交生成文件前用不带这个开关的默认构建，`data_meta.js` 里不能有 `title_song`。
