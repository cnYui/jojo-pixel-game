原图和元数据继续保存在 `assets/bg/`、`assets/_meta/`。输入是仓库外只读的 `D:/CodeWorkSpace/jojo5_art_out/p4bg/`，不会复制清单、底图或成图进仓库。处理结果写入 `assets/bg_gpt/bg/<背景>/<图层>.png`，构建仍使用原来的 `bg/<背景>/<图层>` 资源键、分包、视差系数和 320×180 分辨率。

`--src <目录>` 可以指定另一份相同结构的只读输入。默认按背景键整组启用：清单中该键的全部任务，包括 near、far、variant，都有可解码的成图才接入。缺图和解码失败会让该组回退，失败详情和未列入清单的开关叠加层记录在 `assets/bg_gpt/_report.json`；解码失败时返回非零退出码。`--partial` 允许预览已有层，并在报告和对照图中标明 partial；预览后重新运行默认命令并构建，恢复整组门槛。

画布裁切复用生成脚本的居中 band 算法，按成图实际尺寸换算裁切矩形，BOX 缩回原图层尺寸，再做最多 96 色的无抖动量化。near 在全图按洋红阈值抠色，原轮廓内部的幕布也透明；原图 alpha ≥128 的区域向外膨胀四个游戏像素作为外圈限制，保留新增顶面、侧面并去掉远处杂点。缩小后的 alpha 按 128 二值化，残余偏粉像素置透明，不再使用原图像素补边。

原图已经存在的近洋红物件单独匹配：仅在原图同位置不透明、原色命中洋红阈值且与纯洋红的 RGB 总距离至少 60 时，允许保留每通道偏差不超过 24 的生成色；生成色也必须与纯洋红保持至少 60 的总距离。纯洋红始终透明。这个例外只影响抠色判定，输出颜色仍来自生成图。位置或颜色变化较大的紫红物件仍可能被抠除，应在对照图中检查。

`wrap=true` 图层缩小、抠色和量化后，在右端 2–16 游戏像素的重叠带寻找逐行最小误差缝，缝后使用左端对应像素的镜像；误差同时考虑预乘 RGB 与 alpha，相邻行的缝位置最多移动一像素。左右最外列的 RGBA 完全一致，不使用模糊滤镜，不产生额外颜色和半透明像素。接缝附近会有很窄的镜像区域，应检查跨边界的大物件。

清单中所有图层，包括带 `key` 的开关变体、嵌套层和 fg 前景层，都参与整组检查并输出替换图；构建对开关变体使用相同替换规则。只有不在清单里的小叠加层保留原素材。默认整组门槛仍然生效，单张成图不代表该组已经启用。

重复运行相同输入得到相同 PNG 和报告。每次根据当前输入重新计算全部输出，删除 raw 后重跑会撤下失效组的旧替换图；随后必须重新构建才能更新运行时包。`assets/bg_gpt/` 是流水线专用目录，不要手放素材。构建排除此目录的额外资源键，只在原图有替换时读取替换图。

报告的 `unplanned` 列出元数据中尚未进入清单的背景，`unrecognized_raw` 列出不匹配任务名的成图；这两类输入不会被自行猜测映射。当前 115 项清单已经包含 `national_road` 四个循环层、`transmission_tower` 嵌套层和两个 fg 前景层。

对照图在 `tools/dev/_out/bg_compare/<键>.png`，左旧右新，均按最近邻放大四倍。脚本通过现有 Node Playwright 和生产 `engine/bg.js` 绘制，展示左中右镜头、竖向卷动端点、默认状态、每个开关以及全部开关开启的效果，不需要安装包。
