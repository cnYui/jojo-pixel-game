## 2. 和技术约定的偏离

| # | 本文怎么写 | 实际怎么做 | 为什么 |
|---|---|---|---|
| 1 | §5.8 收字：`engine\*.js` 等文件里“所有码点 > 127 的字符” | JS 文件先去掉 `//` 和 `/* */` 注释再收（`strip_js_comments`，认得三种引号字符串） | 包 2 的 `px.js` 注释里写了 `−`（U+2212，simsun 没有），照字面收会让 font 步每次报缺字失败；注释不会画到屏幕上 |
| 2 | §3.9 `fxtex: { noise, ankh }` | 另加 `ankhPad: {S: pad}`、`ankhScale: {S: k}` | `_ankh_field` 返回的 pad 是 `fire_ankh` 定位要用的；scale 现在都是 1.0（解码 `core = R/255·k`）。只加字段，不改原字段 |
| 3 | §3.5 `speakers` 来自 `text.SPEAKERS` | 另把名牌登记表里“不是主角、也不在 SPEAKERS 里”的人补进去（现在是 `grayfly`：名字 = 名牌 cn，名字色 = 名牌 accent，blipHz 360） | 第 1 战格雷·弗莱要说话，SPEAKERS 里只有 holly / dio |

| 5 | §7.6 `bg` 配方抛错 → “这一步用兜底” | 抛错时**保留已经完整导出的背景**（有图层、引用的图都登记了），半截的丢掉（连同它登记的图），缺的 key 再用兜底快照补 | 7B 的 `build_all` 一个文件没写好就整体抛错，全扔掉会让已经导出好的 10 张也退回快照 |

## 5. 已知问题

1. **ffprobe 读 `assets\video\*.webm` 时偶尔打印 `Error parsing Opus packet header`**：同样的字节拷到别的目录再读就不报；Chromium 播放正常（自测通过）、mp4 无此提示。没再深挖，集成时如果 Safari / Firefox 有问题再看（它们会先选 webm 还是 mp4 由 `canPlayType` 决定）。
2. 背景兜底快照只有一张 static（没有动画层）；横卷背景（`hongkong_night` 960 宽）用的是 320 宽的快照，静态层固定在屏幕上，走动时背景不跟着卷——等 7B 导出后自动替换。`school_infirmary` / `plane_cabin_side` 的兜底是借 `kujo_bedroom(day)` / `plane_cabin` 顶替。
3. `assets\bg\` 里留着以前兜底快照的旧 `base.png`（现在由 7B 导出的 key 不再引用它们）；data 步只认 `img_index`，不会进运行时数据。按铁律没删。
4. 字库现在只有当前剧情文本的 540 字；剧情写完后要重跑 `font data`（缺字会让 font 步报错并列出出处）。
