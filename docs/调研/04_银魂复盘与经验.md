## 0. 先看结论

1. 银魂的底子可以直接复制过来改：纯 Canvas + 原生 JS，`file://` 双击就能玩，固定 60 Hz，剧情用 async/await 一句句写，资源由 `build_assets.py` 导出、元数据都内嵌在 `data.js` 里，用 `playtest.py` 自动通关测试。《无职转生》就是复制过来改的，银魂原件一个字没动。

## 1. 银魂游戏的形态和文件分工

### 1.1 运行约定（照搬）

- **不用服务器也能跑**：
  - 元数据全部内嵌在 `data.js`（`window.GAME_DATA`），由 `tools\build_assets.py` 的 `build_data()`（:740-751）生成，别手改。
  - 图片用 `<img>`（`G.image` / `G.preload`，`engine\core.js:45-63`），音频用 `HTMLAudio`（core.js:129-188），过场视频用 `<video>`（`engine\script.js:425-462`）。
  - **不用 fetch / XHR**：`file://` 下会被拦。
- **画布**：
  - 384×216，就是银魂原片的内部画布。
  - 所有东西先画到离屏的 `G.view`，最后一次性按整数倍、最近邻放大到屏幕上（`G.resize` core.js:73-86，`render()` :220-240）。
- **固定 60 Hz 逻辑**：
  - `STEP = 1/60`；每个 rAF 最多补 6 步，补满 6 步就把累积时间清零（core.js:202-251）。
  - `G.time`（暂停时不走）和 `G.realTime` 分开记。
  - 命中顿帧：`G.hitStop > 0` 时 update 直接 return（core.js:210）。
- **`file://` 下读不了画布像素**：画进画布的图片算跨域，`getImageData` 会报错。所以像素效果只用这三种办法：
  - 画布 CSS 滤镜。冲击帧就是这样做的：`'grayscale(1) contrast(12) invert(1)'`（core.js:236）。
  - 离屏画布加 `source-in` 合成来染色，按颜色缓存（`engine\gfx.js:25/121/137`，`tintImg`）。
  - 构建时预先渲染成图片。
- **脚本载入顺序**（`index.html:127-150`）：data.js → engine/core → gfx → world → ui → script → touch → story/stages → prologue → chapter1…14 → main.js。全局只挂一个 `window.G`。

### 1.3 主流程（`main.js`）

- `G.CHAPTERS`（main.js:8-24）：每章写成 `{ key, title, run: (S) => G.STORY.chapterN(S), end: '第N章　完', next: '下一章：…' }`。
- `G.playFrom(idx)`（:85-102）：
  - 从第 idx 章一路跑到最后一章；
  - 每章开始先 `G.world.free = false`（章节切换时不交还操作，见坑 B1）；
  - 每章跑完清空 `G.flags`；
  - 全部跑完进 `endScene`（:111-130），显示 `ch.end` / `ch.next` 和“同人像素致敬作品”声明。
- `G.goTitle()` 会做 `G.runId++`。正在跑的剧情靠检查 `runId` 自己失效（script.js:19、main.js:94），所以回标题不会残留剧情。
- 标题曲优先放 `title_song`（:140）。浏览器第一次按键之后才补放（`kick`，:252-257；在手机上手指抬起才算用户激活）。

## 2. 剧情写法

### 2.1 一章一个文件

- **文件头注释写整章流程**，范例是 chapter1.js:1-2、chapter13.js:1-11。整个文件包在 IIFE 里，最后定义 `G.STORY.chapterN = async function (S) {…}`。
- **主函数骨架**（chapter1.js:389-435）：

  ```js
  G.STORY.chapter1 = async function (S) {
    G.fadeAlpha = 0; G.world.stage = null;
    await S.chapterCard('ch1');
    const p = new G.Actor('gintoki', 90, 151, { id: 'player', team: 'player', hp: 100, speed: 72, name: '银时' });
    G.world.player = p;
    G.fadeAlpha = 1;
    await S.setStage('office_ch1', { x: 90, y: 151 });
    await S.run(async (S) => { /* 开场剧情，跑完自动交还操作 */ });
    await S.until(() => G.flags.landed);      // 自由探索里，调查点 / 触发区会把剧情往下推
    await S.until(() => G.flags.ch1Done);
  };
  ```

- **地图**：
  - 基础几何写在 `story\stages.js` 的 `G.STAGES.xxx`：`{ id, bg, x0, x1, yMin, yMax, music, props, obstacles, kind }`。
  - 每章派生自己的版本（chapter1.js:360-386），比如 `Object.assign({}, G.STAGES.street, { id: 'street_ch1', npcs, hotspots, triggers })`。
  - **同一张图在不同章要派生不同的 id**。GPT 第二章直接复用了 `street_ch1`，结果街坊说的还是第一章的话，第一章的混混战还会重新触发。
  - **地图 id 必须以 `_chN`（后面可带 b）结尾**。`playtest.py:61-68` 的 `chapter_of()` 靠它判断“换章了”。
- **三种互动对象**：

  | 类型 | 写法 | 说明 |
  |---|---|---|
  | NPC | `{ cid, id, x, y, facing, anim, talk: async (S) => {…}, label, alt, talkRy }` | `label` 是头顶 ▼ 提示上的名字，自动测试 `use_npc(label)` 也按它找人，同一张图里要唯一；`talkRy` 是能搭话的前后距离（默认 14，坐在桌子后面的人给大一点）；`alt` 是原片特殊动作的附加图集，优先用 |
  | 调查点 | `{ id, x, y, r, ry, label, lx, ly, use: async (S) => {…} }` | `r` / `ry` 是调查半径，**别盖住旁边的 NPC**（坑 B10）；`lx` / `ly` 是提示的位置 |
  | 触发区 | `{ id, x0, x1, cond: () => bool, run: async (S) => {…} }` | 玩家走进 x0–x1、并且 cond 为真时跑（chapter1.js:383-385） |

- **状态**：
  - 用 `G.flags`，每章清空。
  - NPC 反复搭话时换句，用计数器 `count('otoseN')`（chapter1.js:7、192）。
  - 推进剧情的标记写成 `landed` / `thugs` / `beatThugs` / `ch1Done` 这样的名字。
- **`S.run(fn)` 一次只跑一段**：跑的时候锁住玩家（`W.free = false`），跑完交还（script.js:12-22）。**不要在 S.run 里面再嵌套 S.run**：它会一直等上一段跑完，永远等不到（《无职转生》踩过）。
- **前后章的伏笔**：第一章抽屉里那张过期优惠券（chapter1.js:44）在第二章开头用上；私房钱“本来是留着吃巧克力芭菲的”（:82）。

### 2.2 剧情 API（`engine\script.js`）

| 类别 | API |
|---|---|
| 说话 | `S.say(cid, 文字, { expr, name, actor, color, sfx })`（:170；说话人有 talk 动作就自动播放）；`S.say(null, …)` 是没有名字的说明框；`S.narrate(文字, { auto, top, onBlack })`；`S.choice([...], title)` 返回选中的序号 |
| 动作 | `S.walk(a, x, y, { speed, anim, endAnim, face, backward })`、`S.arc(a, x, y, 高度, 秒, { anim, z1 })`（被踢飞、跳下）、`S.pose(a, anim, { freeze, x, y })` / `S.unpose`、`S.act(a, anim, { speed, keep })`（等动作播完）、`S.face`、`S.spawn(cid, x, y, o)`、`S.remove`、`S.follow(a, target)` |
| 镜头 / 画面 | `S.camera(x | 角色 | null)`、`S.zoom(倍数, x | 角色, y, 秒)`、`S.letterbox(on)`、`S.shake`、`S.flash(秒, 峰值, 颜色)`、`S.impact(帧)`（冲击帧）、`S.fadeOut` / `fadeIn`、`S.filter('sepia(0.85)')`、`S.insert(fn)`（全屏特写，只有一个槽）、`S.state(key, val)`（地图画面状态：墙洞、乌鸦、光束）、`S.door(open)` |
| 提示 / 卡片 | `S.hint(文字, 秒)`、`S.nameCard(cid)`（2.6 秒）、`S.chapterCard(key)`（2.8 秒 + 锣声）、`S.notice({ who, title, text })`（“××加入了万事屋！”）、`S.emote(a, '!', 秒, 颜色)`、`S.word('砰!', a, dy)`（拟声字） |
| 小游戏 | `S.mash({ need: 18, time: 4, decay: 2.5 })`、`S.timing({ speed: 1.1, zone: [0.42, 0.58] })`、`S.rhythm({ notes, window: 0.16, travel: 1.6 })`、`S.runner({ obstacles, speed, endX, onTick, ride })`（自动卷轴，输了从头来） |
| 换人 / 地图 | `S.setPlayer(cid, { keep, hp, name })`（:102-115，新建一个 Actor 顶替原来的主角）、`S.setStage(id, { carry, x, y, facing, music, fade })` |
| 道具 / 动画 | `S.prop({ type: 'sprite' | 'rects' | 'text' | 'custom', … })` / `S.unprop`、`S.animate(秒, (k, dt) => …)`（逐帧动画，k 从 0 走到 1） |
| 音频 | `S.sfx(名, 音量, 速率)`、`S.music(名, 淡入秒)`、`S.stopMusic` |
| 过场视频 | `S.video(name)`（放的时候先把 `G.fadeAlpha` 清零、放完再还原，见坑 B13） |

### 2.3 `S.fight(spec)` 的参数（script.js:264-422）

| 参数 | 作用 |
|---|---|
| `arena: [x0, x1]` | 锁住场地 |
| `waves: [[敌人, …], …]` | 一波一波打。敌人写成 `{ cid, actor（剧情里已经站着的人）, id, name, hp, boss, scale, speed, range, moves: ['E_SLASH', 'E_PUNCH', 'E_HEAVY', 'E_GUN' …], side, y, ranged, noCharge, minHp, koTo, onKo, koImpact, dmgMul, idle }` |
| `onWave(S, 第几波, 这波的敌人, attempt)` | 每波开始时插一段剧情。用 `attempt === 0` 让重来时少说几句 |
| `events: [{ when: (t) => 条件, run }]` | 打到一半停下来演一段，再接着打 |
| `endWhen: () => 条件` | 剧情喊停（例：头目只剩一点血，换阿妙出场收拾）。成立就算赢 |
| `allies: [id]` | 同伴一起打，打完变回 NPC（照样跟着走） |
| `vip` / `vipHp` | 护送目标。他倒下也算输 |
| `timer: { label, until }` + `survive` | 右上角倒计时，撑到时间就算赢 |
| `reinforce: { every, max, make(i) }` | 打的过程中不断有人从两边冲进来 |
| `music` / `after` | 战斗曲（默认 `battle`）、打完换的曲子（`null` 就不换） |

- 重来的逻辑：
  - 只重新生成已经上过场的敌人（:331）；
  - 剧情指定的头目重来时**还用原来那个对象**（`e._obj`，:335-348），这样打完以后剧情里拿着的引用不会落空。
- 输了弹「××倒下了…… / 再来一次 / 回到标题」（:398）。每场开始玩家回满血；打完把 `G.ui.hints` 清空（:413）。

### 2.4 战斗数值（`engine\world.js`）

- **出招表**（:7-26）：

  | 招式 | 伤害 | 判定距离 | 击退 | 说明 |
  |---|---|---|---|---|
  | COMBO 1 / 2 | 8 / 8 | 2–31 / 2–29 | 34 | 下劈 / 上撩，26 fps |
  | COMBO 3 | 14 | 2–39 | 140 | 突刺，`heavy`，出拟声字 |
  | AIR | 10 | -4–30 | 70 | 空中跳斩 |
  | E_SLASH / E_PUNCH | 9 / 7 | 2–29 / 2–23 | 80 / 60 | 15 fps |
  | E_HEAVY | 16 | 2–34 | 150 | Boss 重击 |
  | A_SLASH / A_UP | 6 | ~30 | 40 | 同伴，比玩家弱，主要负责牵制 |
  | 远程 E_GUN / E_BAZOOKA / E_KUNAI / E_NEEDLE / E_PISTOL | 4–14 | — | — | 第 `fire` 帧射出 `shot`；`explode` 是爆炸半径 |

- **判定**（:240-243）：只打身前 reach 范围；纵深差 ≤ 8×scale；高度差 ≤ 26。防御只挡正面（:250）。
- **节奏**：
  - 同时最多 2 个敌人出手（`maxTokens: 2`，:154）。
  - 出手前头顶出“!”预警：杂兵 0.32–0.5 秒，Boss 0.5 秒（:633-635）。
  - Boss 冲锋：距离 > 70 且在同一纵深时有 50% 概率；先闪红 0.5 秒、头顶“!!”（:626-629）。
  - 被打后无敌：玩家 0.55 秒、同伴 0.4 秒（:269-270）。
  - 顿帧：普通 0.05、重击 0.09；Boss 被打飞时 0.3 秒，加震屏、白闪和「咔嚓!」（:271、:291）。
- **同伴**：
  - 倒地 2.2 秒后自己爬起来，回 60% 血，1 秒无敌（:507-511）。
  - 小兵有 40% 概率去打同伴，Boss 只盯玩家（:548-559）。
  - 阵营：`side()` 把玩家和同伴算成一边（:29）。
  - 跟随：都站在目标身后固定 28 px（:481）。**6 人队必须改**，见坑 B15。
- **被打飞**：敌人飞上天变成星星（:577-582，银魂梗）。`koTo` / `onKo` 可以指定落点和落地后的剧情（打穿墙）。

### 2.5 画面的惯例

- 原片镜头“照原片的画法重做”，用这些工具：全屏特写 `S.insert`、冲击帧 `S.impact`、集中线 `G.fx.speedLines`、名牌、篇章卡、拟声字、染色 `tint`（石化的灰、中毒的紫、炸黑的脸）。
- `S.insert` 只有一个槽。第十三章自己维护了一个“画面上层”列表 `OV`（chapter13.js:32-50）：按 z 排序、到时间自动删、`clearOverlays()` 一次清空，不跟着镜头推近。盖在人物上面、跟着世界走的东西（火星、灰、樱花）用 `S.prop({ type: 'custom', depth: 9000 })`。
- 没有台词的镜头，靠 `G.dbg = { shot: '名字' }` 让自动测试截一张图（chapter13.js:30、chapter14.js:27）。
- 名牌写在 `build_assets.py:515` 的 `NAME_CARDS` 或 `bg_chapters.NAME_CARDS`，格式 `("标题", "身份｜特点·特点", "LATIN")`。键可以写成「角色@别名」，同一个人在不同章用不同的名牌。第三个值不写时显示角色名；如果标题和角色名相同，名字会显示两遍（坑 A8）。篇章卡写在 `CHAPTERS = {"ch1": ("第一章", "万事屋阿银")}`（:524）。

## 3. 台词规则

1. **台词要多，要符合原著的人物性格和梗**。用户第一句要求就是“需要你添加更多符合原著的台词”。
2. **新写的台词不冒充原作原句**。README 写明“台词按原作的人物性格和梗写，大部分是新写的，不是原作原句”。分镜里原有的台词原样保留，第二章那五句（“地球猴子！上菜慢死了！”等）在规划和 README 里都逐条列了。
3. **设定不确定的宁可不写**，写之前先核对。银魂当时列了要核对的点：道场的欠债经过、神乐出场时的黑道、近藤的决斗、托西、吉原的人物关系、将军的梗、虚的设定。
   - 例：高杉在序章只被提到、不出场，避开战时眼睛的设定问题。
   - 例：神乐那段只写“被黑道追”，不写违禁品。
4. **敏感内容克制**：吉原只写街景，松阳和高杉的死照原片那样克制处理，不画血；柏青哥只当搞笑桥段，不出现真实的赌博规则。
   - 《无职转生》加了一条：未成年人的性暗示和猥琐桥段一律不做。
   - JoJo 第三部同理：阿布德尔、伊奇、花京院之死，还有断手等镜头，都要克制。
5. **人物口癖**：银时死鱼眼、甜党、歪理多；新八吐槽；阿妙笑着说狠话；神乐句尾带“阿鲁”。JoJo 要先列一张各角色口癖表（承太郎“やれやれだぜ / 真是够了”等），再开始写。
6. **对话框的格式限制**：
   - 每秒打 22 个字（`CPS`，ui.js:5）；
   - 宋体 12 px；有说话人时每行宽 318 px，旁白式说明 352 px（ui.js:45）；
   - 两行一页，自动分页（:46-47）；
   - 对话框是 `BOX = { x: 6, y: 170, w: 372, h: 42 }`（:6），头像 2 倍、裁在框里。
   - 这些都是按 384×216 定的，换成 320×180 要重排（见第 13 节）。
7. **说话人显示的名字**：查 `G.NAMES`（stages.js:8-12），没有再用图集名，可以用 `{ name: '团子店大婶' }` 覆盖。路人反复搭话要换句（用计数器）。
8. **提示文字里的键名要和屏幕按键一致**（J K L E）。这样“按 J 停下转轮”在手机上也对得上。操作说明分键盘版 `HELP` 和触屏版 `HELP_TOUCH`（main.js:25-43）。

## 5. 资源构建（`tools\build_assets.py`）

- 用法：`python tools\build_assets.py [chars bg ui audio video font data]`，不带参数就是全部（不含 video）。每一步把元数据写进 `tools\_meta\<步骤>.json`，最后 `data` 这一步合成 `data.js`。
- 文件开头（:21-37）：
  - `sys.dont_write_bytecode = True`，不在源码目录留 `__pycache__`；
  - `sys.path.insert(0, SRC)` 再 `os.chdir(SRC)`，直接 import 原工程的 `engine` / `chars` / `bg` / `scenes`，**按原工程的公式导出**，不凭眼睛临摹。

| 步骤 | 做什么 | 要点 |
|---|---|---|
| `chars`（:69-108） | 把 `..\角色图集\*\*.json` 和对应的 png、头像拷到 `assets\chars\`；**另外自动收录 `assets\chars\s*\*.json`**（调研里直接烘好的特殊动作，:88-100）；记下说话音高 `voice`（原工程的角色参数，用于打字音） | 衍生造型的范例：`derive_chef()`（:111-139）把原片的厨师帽逐帧贴到路人配色 2 上，生成 `townsman__chef`，格子加高 8 px、脚点跟着下移 |
| `bg`（:143 起；第二章 `build_bg_ch2()` :377；第三章起 `bg_chapters.ch3()…ch14()`） | 按原工程 bg 模块的图层和公式导出：视差各层、会动的零件（吊灯 8 帧、拉门 7 帧、樱花树 3 帧……）**和底图分开导出**，在 JS 的图层类型里照原片的公式画 | 第十三章、终章直接拷调研里导出、逐像素核对过的 `test_s13\out`、`test_s14\out` |

| `font`（:699-736） | 见第 4 节 | |
| `data`（:740-751） | 合成 `data.js` | 银魂现在 503 KB |

- 原片里的特殊动作有两条路：一是烘进图集库（`..\烘焙脚本\bake_scene_extras.py sNN`，产出 `角色__sNN`）；二是直接用调研里烘好的（`assets\chars\sNN\`）。角色代码里用 `alt` 挂上，优先用附加图集。

## 7. 录屏

- **用户的规则**：录屏是给短视频 / 长视频当素材，**只录精彩片段**（开场：标题 + 开场动画 + 第一场战斗；结尾：最终决战 + 片尾；中间挑几场打斗），**用户明说“整部都录”才录全程**（2026-10-06 那次录了 53 分 14 秒）。**给用户看的一律是 mp4**。BGM 和音效各出一条单独的轨，三条都对齐 0 秒。
- **工具**：

  | 工具 | 作用 |
  |---|---|
  | `playtest.py 章节 --record 目录` | 起本地 http 服务器（file:// 下画布和音频算跨域，录不出来），窗口就是游戏原尺寸 384×216。对话等字打完、按字数留出读的时间再翻页（`can_skip`，:143-158），等待时间放宽 4 倍。录完写 `run.json`（marks 里有篇章卡 / 过场 / 战斗的时间点） |
  | `recorder.js` | 注入页面：画面 + 混音一条，BGM、音效各一条（WebAudio 分两路总线，不接扬声器） |
  | `webm_to_mp4.py` | 只转画面 + 混音那条，出 1080p60 mp4（最近邻 ×5，章节嵌进文件） |
  | `make_recording.py` | mp4 + BGM wav + 音效 wav + 章节时间点 |
  | `make_clips.py 片段表.json 输出目录` | 按起止时间剪片段，不用重录 |
  | `record_all.py <目录> [--only B]` | 整部分四段录（A 序章–第三章 / B 第四–第七章 / C 第八–第十章 / D 第十一章–终章），每段录完自动查帧率、空档、超时、报错，有问题只重录那段 |
  | `join_chunks.py` | 四段在下一章篇章卡出现的那一刻接起来，不拼 `_` 开头的目录 |

- **技术要点**：
  - `captureStream()` **不传帧率**（传 60 只录到 51 帧左右）；
  - 录的时候不跑 x264 之类的重活，录完逐段查帧率；
  - 录屏前先用快速测试确认没有 `advance_timeout`（录屏模式等待 ×4，会变成几分钟一动不动的画面）；
  - 等待时用 `idle()` 不停 `page.evaluate`，不要 `time.sleep` 干等（不然数据块不及时写盘，:171-176）。
- **宣传片的偏好**（用户对 GPT 剪的版本提过意见）：用不同的手法剪出“炫酷”的感觉；剪辑点卡歌的鼓点，一种手法别用到底；不剧透结局；去掉对话框和操作提示；别把底部字幕裁成半行。范例：`..\录屏素材\2026-10-04_精彩展示\build_trailer_v2.py`。
- **JoJo**：320×180 ×6 = 1920×1080，正好整数倍。如果做了 640×360 的 UI 层，就用 640×360 ×3。

### G. 反面教材：GPT 第二章初稿被整章重写的原因（`_旧稿\GPT第二章_20261003\`）

1. **原片镜头大多用旁白带过**：“芭菲飞起来碎在地上”“乌鸦飞过：阿～呆～”“银时的灵魂离开了身体”都只是一句旁白；导出了眼睛、煎蛋、芭菲的特写却没用上；店长没戴厨师帽；墙上没有洞。
2. **大街直接用第一章的地图配置**：街坊说第一章的话，还会重新触发第一章的保护费战斗。
3. **同伴的毛病**：银时会打到新八；敌人只打玩家；新八不跟着走。
4. **道场门口**：地图 640 宽，背景却是一张不会动的图；阿妙一开始就站在门口。
5. **章末和测试**：章末文字改成模板，测试识别失效，连带第一章的测试也坏了；`playtest.py ch2` 没跑通。
6. README 标题写错。

可以留下的只有思路和小件：标题加章节入口、名牌、篇章卡、在 index.html 里引入新章节。

## 10. 每章开工前后的流程（设计 → 实现 → 自动测试 → 复盘）

银魂第三章到终章每章都是这样做的（`流程复盘.md` 第十三节、`后续章节规划.md` 第七节）。

### 10.1 开工前：调研 + 设计

1. **读原片**：
   - 分镜：`..\剧情分镜\场景分镜\sNN_*.md`（设计意图、镜头表、台词、音效）和 `..\剧情分镜\分镜图\sNN_*.png`（每 0.5 秒一帧的联系表）；
   - 原场景代码：`..\源码\scenes\sNN_*.py` 和美术模块 `_sNN_*.py`。
2. **写调研 brief**：`docs\章节素材调研\sNN.md`，格式参照 `s14.md`：
   - §1 Beats 表：`| t | shot | set / camera | action | text |`，逐镜头写时间、机位 / 推近、站位坐标、动作、台词、拟声字；
   - §2 Sets：每张布景的图层顺序、脚点 y、可走范围、关键物件的世界坐标，加上**测过的导出代码**（可以直接贴进 build_assets / bg_chapters）；
   - 测过的脚本和输出放在 `test_sNN\`（`out\` 里是逐像素核对过的导出结果）。
3. **写详细设计**，格式照 `后续章节规划.md` 第三节：
   - 3.1 目标：照分镜，再补出“自由探索 + 战斗 + 解谜”需要的段落；
   - 3.2 地图：原工程的来源函数和常量（地板 y、门窗坐标、可走范围）；
   - 3.3 角色：用到的动作**先在图集里核对过存在**；
   - 3.4 流程：编号列每一段，标注〔过场〕〔自由〕〔战斗〕〔解谜〕，写清能调查什么、能聊谁、战斗几波、谁当同伴、原片名场面怎么重做；
   - 台词：分镜原句原样保留，其余照人物性格新写；
   - 3.5 要改的文件表；
   - 3.6 验收：命令、要看的截图、两个选项都走一遍、至少输一次。
4. **要用户拍板的事列出来**；用户没回就按默认做，写进规划开头。

### 10.2 实现

1. 导出布景和道具：`tools\bg_chapters.py` 里的 `chN(stages, c)`；名牌、篇章卡写进 `NAME_CARDS` / `CHAPTERS`。
2. 原片的特殊动作：烘进图集库（`..\烘焙脚本\bake_scene_extras.py sNN`），或者放进 `assets\chars\sNN\`（chars 那一步会自动收录）。
3. 写剧情 `story\chapterN.js`（地图派生成 `xxx_chN`）；在 `main.js` 的 `G.CHAPTERS` 加一项；`index.html` 引入新文件；`tools\playtest.py` 加 `route_chN` 并登记进 `ROUTES` / `ORDER`。
4. 引擎需要新功能就加进 engine，写成通用参数（例：`S.fight` 的 `events` / `reinforce` / `dmgMul`），不在章节里硬写。
5. 构建：`python tools\build_assets.py bg chars ui font data`。

### 10.3 自动测试

1. `python tools\playtest.py chN`：打到章末；看控制台 0 报错、截图逐张看（名牌、篇章卡、特写、对话框不出框；同伴不挡路、不卡墙；镜头对得上原片）、`trace` 里没有长时间空等。
2. 输一次：至少一个 Boss 用 `--lose`，或者单独写一个小测试。
3. 回归：做完一部或改过引擎之后，跑 `python tools\playtest.py all`（34 分钟左右）。
4. 改了触屏相关的：`python tools\touchtest.py`。

### 10.4 复盘 / 留痕（每章都写）

1. 游戏的 `README.md`：「内容」一节加这一章（流程、能聊谁、能查什么、战斗）；新的剧情工具写进「改剧情 / 加新章节」。

## 13. JoJo 和银魂不一样、开工前要定的地方（给总负责人）

1. **画布分辨率**：
   - JoJo 原片的基础画布是 320×180，UI 层是 640×360（`D:\大疆\游戏素材\JoJo\源码\engine\core.py:13-16`：`W, H = 320, 180`；`UW, UH = W * UI, H * UI  # 640 x 360`；`engine\text.py` 的文字画在 UI 层上）。
   - 银魂游戏的对话框 `BOX {x:6, y:170, w:372, h:42}`、换行宽度 318 / 352 px、12 px 宋体、标题和章节页的坐标（main.js:145-154 的 `tapRow`、185-230 的 `draw`），全都按 384×216 写死了。
   - 两个方案：
     - (a) 世界画在 320×180，文字 / UI 画在 640×360 的第二块画布上（和原片一样，字更清楚；`G.resize` 改成按 320×180 算整数倍，UI 层用一半的倍数）；
     - (b) 全部画在 320×180 上，用 12 px 字（每行只能放二十来个字，很挤）。
   - 我倾向 (a)。录屏：320×180 ×6 或 640×360 ×3，都是 1920×1080。
2. **按键语义不同**：
   - 银魂：K = 跳（空中按 J 是跳斩，自动卷轴里 K 跳障碍）；L = 按住防御（只挡正面）。
   - JoJo：K = 闪避（残影 + 短暂无敌），没有跳跃；L = 替身格挡；U = 替身必杀（要攒满能量槽）。
   - 要改的地方：`engine\core.js` 的 KEYMAP（:94-100，要加 U）、`world.js` 的 `updatePlayer`（:386-471）、提示文字、`HELP` / `HELP_TOUCH`、触屏按钮（加一个 U 钮）、playtest 的 `special()` 和 `fight()`（:211-216 按 k 跳、:330 起只会连按 J）、`STATE_JS` 加能量槽。
3. **欧拉连打和确认键冲突**：见第 12 节第 8 条，要先定好输入规则。
4. **6 人随时换队长**：
   - 银魂的 `S.setPlayer`（script.js:102-115）是剧情里的一次性换人，会 new 一个 Actor 顶替原来的主角。
   - JoJo 要在自由走动时一按键就换，原队长留下来当跟随者。要定的事：换人键是哪个；战斗中能不能换（用户只说了“自由走动时可以随时换”，战斗里要问）；剧情里不在场的人（花京院中途离队、阿布德尔“假死”、伊奇半路才加入）怎么从可选名单里拿掉、再加回来。
5. **替身和替身使者同场**：银魂的敌人是单个 Actor。JoJo 的替身要跟着本体（出现 / 收回、位置偏移、远程替身离本体很远，还有“打替身本体也受伤”）。Actor 要能挂一个替身子对象，命中判定按替身和本体分开写。
6. **章节怎么切**：银魂是一个分镜场景做一章。JoJo 用户要“打全部替身使者、完整的第三部剧情”，远多于分镜里的 21 个场景（s00–s20）。章节表要另外排（按原作的替身使者顺序），分镜里没有的部分要自己设计、缺的角色重新画。**每章开工前照第 10 节写设计**。
7. **“战斗爽”和炫酷特效**：银魂的打击感参数（顿帧 0.05 / 0.09 / 0.3、震屏、火花、拟声字、Boss 被打飞时冲击帧 + 集中线）可以当起点。JoJo 要另外加：欧拉 / 木大连打的拳影墙、「ゴゴゴ」拟声字、时停的反色和静音、替身出现时的残影。性能一律按坑 B14 的教训来做。
8. **版权**：标题曲 STAND PROUD 是商业歌曲，角色是同人形象，处境和银魂的 title_song 一样：只在本机，公开发布或录屏发平台之前要先想清楚授权。章末加上“原作：荒木飞吕彦《JoJo 的奇妙冒险》｜同人像素致敬作品”（照 main.js:126 的写法）。
