## 0. 结论先说

1. 银魂版是**单层 384×216 低分辨率画布**（`core.js:5-6`），世界、文字、界面全画在这一张上，再整数倍最近邻放大到屏幕画布。文字用**宋体点阵字图集**（12 / 16 px），界面坐标全部是写死的 384×216 像素坐标。
2. 引擎能直接搬的：主循环 / 输入 / 音频 / 等待（`core.js`）、点阵字类 `Font`、图集类 `Atlas`、特效粒子 `G.fx`、UI 状态机（对话 / 选项 / 旁白 / 菜单 / 篇章卡 / 提示 / 系统框 / 小游戏）、章节流程（`G.CHAPTERS` + `playFrom`）、触屏层（`touch.js` + `index.html #tc`）、`data.js` 打包方式。要重写的：所有界面坐标、标题 / 章末画面、背景图层类型（银魂专用的那一半）、HUD（加替身能量条、队长切换）、按键表。
3. **画布建议：世界层用 JoJo 原片的 320×180，界面另开一层 640×360（2 倍，宋体 16 px 正文）**，和 JoJo 原工程 `engine/core.py:13-16`（`W,H=320,180`、`UI=2`、`UW,UH=640,360`）的分层一模一样。屏幕按 320×180 的整数倍 s 放大，UI 层按 s/2 放大（s 为奇数时 UI 是 2.5 / 3.5 倍，笔画 2、3 像素交替，实测能接受，见 §10）。理由与另一个方案（照搬 384×216）的利弊对比在 §10。

## 1. 渲染管线

### 1.1 画布与缩放（`core.js:65-91`）

| 项 | 值 / 做法 | 位置 |
|---|---|---|
| 逻辑画布 | `G.W = 384`、`G.H = 216`；离屏 `G.view`（canvas 384×216），上下文 `G.g` | `core.js:5-6, 68-71` |
| 屏幕画布 | `index.html:95` 的 `<canvas id="screen" width="384" height="216">`，`G.resize()` 运行时改尺寸 | `core.js:66-67, 73-86` |
| 放大倍数 | `s = max(1, floor(min(innerWidth·dpr / 384, innerHeight·dpr / 216)))`；屏幕画布的**位图**尺寸 = `384s × 216s`（物理像素），CSS 尺寸 = 位图 / dpr → 物理像素上严格整数倍 | `core.js:73-82` |
| 居中 / 不模糊 | CSS `#screen { position:absolute; left:50%; top:50%; transform:translate(-50%,-50%); image-rendering:pixelated; }`；`sctx.imageSmoothingEnabled = false` | `index.html:18-19`，`core.js:81` |
| 重新计算 | `resize`、`orientationchange`（延迟 250 ms）、`visualViewport.resize`、全屏切换（`touch.js:207`） | `core.js:83-86` |
| 屏幕坐标 → 画面坐标 | `G.toGame(e)` = `((clientX − rect.left)·384 / rect.width, (clientY − rect.top)·216 / rect.height)` | `core.js:88-91` |

### 1.2 主循环（`core.js:197-252`）

- 固定逻辑步长 `STEP = 1/60`，每个 `requestAnimationFrame` 最多补 6 步，`dt` 封顶 0.1 s，补满 6 步就丢掉积压（`core.js:241-251`）。`G.suspended`（竖屏时 `touch.js:177` 设）为真时只画不更新。
- `update(dt)`（`core.js:205-219`）顺序：`G.realTime += dt` → 音频淡入淡出 → `G.impactT` 递减 → **`G.hitStop > 0` 时只递减、清输入、直接 return**（整个场景冻住，连打字机都停）→ `G.scene.update(dt)` → 场景没冻住时 `G.time += dt`、震屏计时、`G.wait` 计时器 → `G.until` 条件等待 → `G.input.endStep()`。
- **坑（对“战斗爽”很重要）**：顿帧期间按下的键在 `core.js:210` 被 `endStep()` 清掉，等于丢键。JoJo 要“连按 J 欧拉连打”、命中就顿帧，必须加输入缓冲（记住 0.12–0.15 s 内的按键，顿帧结束后再消费）。
- 场景对象接口：`{ name, enter(), leave(), update(dt), draw(g), get frozen() }`，`G.setScene(s)`（`core.js:199`）。`frozen` 为真时 `G.time` 和 `G.wait` 不走（暂停菜单用，`main.js:50`）。注意 `G.fade` 用的是 `G.waiters`（每步固定加 1/60），暂停时照样走，顿帧时不走。

### 1.3 每帧画图顺序（`core.js:220-240` + `main.js:57` + `world.js:747-805` + `ui.js:164-209`）

```
render():
  G.g 复位（setTransform、alpha=1、source-over、关平滑）→ 整屏填黑
  G.scene.draw(g)                         // 游戏中 = worldScene.draw：
    ├─ G.world.draw(g)                    // world.js:747
    │    有推镜头 zoom 且 k>1：先整幅画到缓冲 zbuf，再截 (W/k × H/k) 放大贴回（world.js:750-758）

    │      2. 背景：st.bg.draw(g, camX, t, st)（视差图层，§3）或 office 型整图（环境帧 / 拉门帧）

    │      4. 前景图层 st.bg.drawFg（默认 alpha 0.5，L.alpha 可改）
    │      5. G.fx.draw(g, camX, camY, false)   世界坐标特效
    │      6. 每个角色头顶：表情字 emote（f16，弹跳）、非 Boss 敌人小血条（20×2，#ff5050）
    │      7. 互动提示框「▼ 名字」（near 目标头顶，上下浮动）
    │      8. G.fx.draw(g, 0, 0, true)          屏幕坐标特效（集中线、星星、阴郁竖线）——注意也在推镜头缓冲里
    └─ G.ui.draw(g)                       // ui.js:164，见 §5
  白闪：G.flashAlpha × G.flashColor 整屏（盖住世界 + UI）
  黑幕：G.fadeAlpha 黑色整屏
  G.ui.drawTop(g)：黑场旁白、菜单（在黑幕之上）  // ui.js:206-209
  G.view → 屏幕画布 drawImage 放大 s 倍；
    G.impactT > 0 时 sctx.filter = 'grayscale(1) contrast(12) invert(1)'（冲击帧：亮变黑、暗变白），
    否则 sctx.filter = G.screenFilter（如回忆 'sepia(0.85)'）；滤镜作用于整帧（含 UI）
```

要点：

- 推镜头（`S.zoom`，`script.js:87-99`）只放大世界，UI 不放大；但屏幕坐标特效（第 8 步）在缓冲里，也会被放大。
- 冲击帧 / 整屏滤镜用的是 canvas 的 `filter` 属性。原因写在 `core.js:234`：`file://` 打开时图片算跨域，画布被“污染”，`getImageData` 读不了像素，只能用滤镜。**所以所有逐像素效果（灰化、反相、描边、外发光）都不能读像素做**，要么用 `ctx.filter`，要么用“剪影图多次偏移叠画”，要么构建时在 Python 里预烘焙。
- 白闪画在 UI 之后，会把对话框一起闪白；JoJo 原片 `fr.flash` 只作用于底层像素层（`JoJo 源码 engine/core.py:265-267`，在缩放、叠 UI 之前），`fr.fade` 才作用于最终合成（`core.py:292-294`）。分层后要照 JoJo 的规矩分开。

## 2. 角色图集绘制 API（`gfx.js:91-185`，`world.js:82-111`）

### 2.1 `G.atlas(cid)` / `Atlas`

- `G.atlas(cid)`（`gfx.js:176`）按 id 缓存 `Atlas` 实例；元数据来自 `G.D.chars[cid]`：`image`、`cell:[w,h]`、`pivot:[px,py]`、`animations:{名: {row, frames, fps, kind}}`、`aliases`、`heads`、`voice`。
- `has(name)`：动作或别名存在（`gfx.js:106`）。`anim(name)`：本名 → 别名 → `idle` → 第一个动作（`gfx.js:107-113`），**缺动作不报错，静默退回 idle**。
- `draw(g, animName, frame, x, y, o)`（`gfx.js:145-173`）：
  - `(x, y)` = **脚点（pivot）在画面上的位置**（屏幕坐标，调用方已减过镜头）；
  - 帧号 `clamp(frame|0, 0, frames−1)`；源矩形 `(f·cw, row·ch, cw, ch)`；
  - 变换：`translate(round(x), round(y))` → `rotate(o.rot)`（**弧度，顺时针为正**）→ `scale(o.flip ? −sc : sc, sc)` → `drawImage(…, −px, −py, cw, ch)`。所以**翻转、缩放、旋转都绕 pivot**，和 JoJo 图集 README 说的“朝左 = 绕 pivot 的 x 翻转”一致，不用改；
  - `o.alpha`：整体透明度；
  - `o.tint = { color, k }`：叠一层同色剪影，透明度 k（石化灰、烟熏黑、黄昏橘）；剪影用 `tintImg(color)` 生成（离屏画整张图集 → `source-in` 填色），**每种颜色缓存一整张图集大小的 canvas**（`gfx.js:129-143`），颜色别动态变（比如别每帧算一个 rgba 字符串），否则内存涨；
  - `o.flash`（0..1）：叠白色剪影（受击闪白），`whiteImg()` 缓存（`gfx.js:114-127`）。
- `G.head(cid, expr)`（`gfx.js:178-185`）：对话头像，查找顺序 `heads[expr]` → `heads['portrait_'+expr]` → `heads.normal` → `heads.portrait_default` → 第一个；`a__b` 这种配色变体没有头像时用本体 `a` 的。

### 2.2 `Actor.draw`（`world.js:82-111`）

- 脚下影子：`fillRect(sx − 6·scale, sy − 1, 12·scale, 2)`，`rgba(0,0,0,0.25)`；`alpha ≤ 0.3`、死亡、旋转时不画。
- 无敌闪烁：玩家 / 同伴 `invuln > 0` 时 20 Hz 交替 `alpha 0.45`。
- 载具 `ride`（小绵羊、警车）：车身图 → 人（抬高 `seat`）→ `front` 前挡 → `light` 车灯（`lighter` 相加）。
- 帧号：`frameIndex()` = `floor(animT·fps·animSpeed)`，`loop` 取模、其余停在最后一帧；`frozen` 定格（`world.js:74-80`）。
- 附加图集 `alt`：本体没有的动作去附加图集找（`world.js:69-72`）。

### 2.3 JoJo 图集和银魂格式的差别（搬的时候要处理）

- json 主体（`cell / pivot / animations[row,frames,fps,kind] / aliases`）完全兼容，`Atlas` 不用改就能画。
- 头像不同：银魂是 `头像\<表情>.png`（normal / happy / angry…），JoJo 是 `expressions` 列表 + `头像\portrait_0.png / portrait_1.png / portrait_angry_0.png…`（32×32，0 = 闭嘴、1 = 说话）。构建时把 heads 映射成 `{ normal: portrait_0, normal_talk: portrait_1, angry: portrait_angry_0, angry_talk: portrait_angry_1 … }`；对话框打字时 8 fps 在 0 / 1 两帧间切、打完停 0（JoJo `text.py:180` 的做法），银魂的对话框是静态头像，要加这一条。有头像的只有 16 个：avdol、darby、dio、enya、holhorse、holly、iggy、jgeil、joseph、jotaro、kakyoin、polnareff、starplat、telence、theworld、vanilla（花京院、波鲁纳雷夫等主角团都有；大部分敌方替身使者没有，要补画）。
- JoJo 原片 `sprite.draw` 还支持 `tint='gray'|'invert'|'black'`、`rot`（**角度、逆时针**）、`outline`（1 px 外描边）、`aura`（替身光环：剪影膨胀 1 px + 抖动 ±1 px，alpha 0.55，`JoJo sprite.py:268-285`）。银魂 `Atlas.draw` 只有剪影染色和闪白，要加：
  - 描边 / 光环：用 `tintImg(color)` 在 (±1,0)、(0,±1)（光环再加对角）偏移各画一次再画本体，不读像素，`file://` 下也能跑；
  - 灰化 / 反相（时停、冲击帧）：`ctx.filter = 'grayscale(1)' / 'invert(1)'` 画，或构建时预烘焙一张灰图集；
  - `rot` 单位换算：`rad = −deg·π/180`。
- 动作极少：主角团每人 6–10 个动作、每个 1–4 帧（`jotaro`: idle / walk / run / sit / point / pose / shock / hurt + 两组头像；替身 `starplat`: idle / punch / rush / block / pose / fist）。银魂战斗代码会叫 `attack / slash_up / thrust / hit / fly / jump / guard / talk` 等名字，缺了都会静默退回 idle。要么在图集 json 的 `aliases` 里补映射（`hit→hurt`、`fly→hurt` 等），要么按“缺的素材可以重画”去补帧。
- 尺寸：JoJo 人物 48–64 px 高（`dio` cell 52×64、`jotaro` 40×52），按 180 高的画面设计；银魂人物约 40 px 高（`gintoki` cell 53×50、pivot 19,40）放在 216 高的画面里。
- 替身是**独立图集**（`starplat` 和 `jotaro` 分开），游戏里要当“跟着本体的第二个精灵”画，`STYLE.md` 写原片替身常用 alpha ≈ 0.85；排序时让替身跟本体同一个 y（±0.1）。

## 3. 视差背景与图层类型（`gfx.js:202-683`）

### 3.1 结构

- `new G.Background(spec)`：`spec = G.D.bg[key]`，`spec.layers`（世界后面）+ `spec.fg`（角色前面，`drawFg` 默认 alpha 0.5，免得挡住打架的人）（`gfx.js:203-215`）。
- `layer(g, L, camX, t, st)`（`gfx.js:217`）：`L.key` 存在时只有 `st.state[L.key]` 为真才画（剧情开关：墙洞、光束、樱花）；`st` = 当前 `Stage`，剧情用 `S.state(key, val)` 改（`script.js:46`）。`t = st.t`（地图自己的时钟）。
- 地图定义（`stages.js`）：`{ id, kind: 'layers'|'office', bg: <G.D.bg 的键>, x0, x1（世界宽度）, yMin, yMax（可走的纵深带）, music, props, obstacles, npcs, hotspots, triggers, camX, state }`。`kind: 'office'` = 固定镜头的整图房间（`world.js:768-772`：拉门开着画 `door[]` 帧，否则按 `amb_fps` 播 `amb[]` 环境帧）。
- 镜头：`updateCamera`（`world.js:733-743`）目标 = 玩家 x − W/2 + 朝向 × 18，被 `[x0, x1 − W]`（战斗时是 `lock` 竞技场）夹住，缓动 `dt·5`。

## 4. 已有特效

### 4.1 `G.fx`（`gfx.js:867-997`）——粒子列表，每帧 `update` 推进、`draw` 画

| API | 效果 | 参数 |
|---|---|---|

## 5. 宋体点阵字：怎么生成、怎么用

### 5.1 生成（`tools/build_assets.py:699-736`）

1. `collect_text()`：扫 `story/*.js`、`engine/*.js`、`main.js` 里**所有引号（' " `）中的字符串**，再加 ASCII 可见字符、常用中文标点 `…—「」『』（）！？，。、：；“”‘’·～＋－×÷■□▼▲►◄★☆♪` 和全角空格 `　`；去掉换行、不可打印字符。
2. `build_font()`：对 12、16 两个字号，`ImageFont.truetype("C:/Windows/Fonts/simsun.ttc", size)`，`lh = asc + desc`（12 px → 11+2 = **13**；16 px → 14+3 = **17**），图集每行 64 字、格宽 `size+1`、格高 `lh+1`；`ImageDraw.fontmode = "1"`（1 bit，不抗锯齿），`d.text((x, y+asc), ch, anchor="ls")` 白色画；`adv = round(getlength(ch))`（全角 = 字号，半角 = 字号 / 2）。
3. 输出 `assets/font/simsun12.png`（832×322）、`simsun16.png`（1088×414），元数据 `font['12'] = { image, lh, asc, glyphs: { 字: [x, y, adv] } }`；现在两套都是 1440 字。
4. **改了任何中文字符串后要重跑** `python tools\build_assets.py font data`，否则缺字。缺字时 `Font.raw` 在控制台警告一次，并退回 `fillText('SimSun')`（抗锯齿、和点阵字不一样，一眼能看出来）（`gfx.js:46-52`）。

实测（本次 scratchpad）：宋体 `simsun.ttc` 在 **12、13、14、15、16 px 有内嵌点阵**（Pillow 普通抗锯齿模式下也只有 2 个灰阶），11、18、20、24 px 是矢量轮廓（几百个灰阶）。所以点阵字只能在 12–16 px 里选；更大的标题字要像银魂 / JoJo 原片那样用黑体 / 微软雅黑粗体**预渲染成图片**。

### 5.2 使用（`gfx.js:7-89`）

- `G.initFonts()` 在启动时建 `G.f12 = new Font(12)`、`G.f16 = new Font(16)`（`main.js:245`）。
- `font.draw(g, str, x, y, color='#fff', { align: 'center'|'right', outline: 色, shadow: 色 })`：`(x, y)` 是**左上角**（行顶）；`outline` = 8 个方向各画一遍再画本体（共 9 遍）；`shadow` = 右下偏 1 px。
- 每种颜色第一次用时生成一张整图集大小的染色 canvas 缓存（`tinted(color)`，`gfx.js:17-31`），颜色种类别太多。
- `font.width(str)`、`font.wrap(str, maxW)`：按 adv 累加换行，**行首禁则**（`，。、！？…」』）～—` 不放行首，直接挂在上一行末尾，`gfx.js:75`），`\n` 强制换行。

### 5.3 搬到 JoJo

- `build_font` 原样能用（JoJo 原片 `text.py:21-23` 的 `'pixel'` 字体就是 `simsun.ttc` 12 / 16）。如果 UI 层用 640×360，正文用 16 px、小字用 12 px，和 JoJo 原片 `tx.dialogue` / `tx.narration`（16 px）、`tx.name_card` 副标题（12 px）一致。
- `collect_text` 要多收：角色图集 json 的 `name`（`空条承太郎`、`J·凯尔`、`瓦尼拉·艾斯`……这些名字不一定在台词里出现）、`G.NAMES` 之外由数据拼出来的字符串。

## 7. 章节流程（`main.js`）

### 7.1 章节表

```js
G.CHAPTERS = [ { key: 'prologue', title: '序章　白夜叉', run: (S) => G.STORY.prologue(S), end: '序章　完', next: '下一章：万事屋阿银' }, … ]   // main.js:8-24，共 15 章
```

- `key`：篇章卡图片的键（`G.D.ui.chapters[key]`）；`title`：选章节页显示的名字；`run(S)`：章节主函数（各章文件里 `G.STORY.chapterN = async function (S) {…}`，例：`prologue.js:189-227`）；`end / next`：章末画面两行字（只在**整条链跑完**时显示最后一章的，见下）。
- 每章的主函数通常：`await S.video()`（可选）→ `await S.chapterCard(key)` → 建主角 `new G.Actor(cid, x, y, { id:'player', team:'player', hp, speed, name })`、`G.world.player = p` → `await S.setStage(地图id, { x, y, facing })` → `await S.run(async (S) => { 开场演出 … S.hint(操作提示) })` 交还操作 → `await S.until(() => G.flags.本章完)`。自由走动期间由地图的 `triggers`（走进 x 区间自动跑一段剧情，`world.js:687-693`）、`npcs[].talk`、`hotspots[].use`（靠近按 E）推进；战斗写在剧情函数里 `await S.fight({ arena, waves, … })`，输了弹「再来一次 / 回到标题」从这场重来（`script.js:272-422`）。
- `G.flags`：每章开始清空（`main.js:87, 95`），章内的剧情开关。

## 8. 触屏布局（`index.html:23-125` + `engine/touch.js`）

### 8.1 原理

- **把手指翻成键盘输入**：按钮按下 `setKey(action, true)` 写 `G.input.down / hits`（`touch.js:27-30`），游戏逻辑一行不改。按钮上的字母（J K L E）和游戏提示文字里的键名一样。
- 点画面 = 确认 + `G.input.tap = 画面坐标`（`core.js:126`；黑边上点由 `touch.js:334-340` 补）；菜单 / 选项 / 标题用 `tap` 判断点中哪一项。
- 何时显示：`(pointer: coarse)` 或手机 UA；`?touch=1 / ?touch=0` 强制；接实体键盘按游戏键就收起（`touch.js:342-343` 的正则 `^(Arrow|Key[WASDJKLZXCEP]$|Enter|Space|Escape|Backspace|Numpad)`），再碰屏幕又出来。
- 竖着拿：`#tc-rotate` 盖住提示横屏，`G.suspended = true` 停游戏（`touch.js:175-177`）。
- 全屏：安卓 `requestFullscreen` + 锁横屏；iPhone 只能“添加到主屏幕”（`touch.js:193-208`）。iOS 声音点播 `primeAudio`（`touch.js:242-281`）。

### 8.2 尺寸和位置（全在 `index.html` 的 CSS 里，JS 不管长相）

- 基准直径 `--b = clamp(round(min(innerHeight·0.145, innerWidth·0.075) × 档位), 36, 96) px`，档位 小 0.82 / 中 1 / 大 1.22，存 `localStorage['gintama-touch-size']`（`touch.js:163-174`）。

## 10. 画布尺寸：320×180 还是 384×216

### 10.1 事实

| | 银魂版 / 银魂原片 | JoJo 原片 |
|---|---|---|
| 像素画布 | 384×216，文字也画在这一层 | 底层 320×180（全部像素画） |
| 文字 / UI | 同一层，宋体 12 / 16 px | **另一层 640×360**（`UI = 2`），宋体 16 px 正文，粗体大字 |
| 成片 | ×5 → 1920×1080，30 fps | 640×360 合成 ×3 → 1920×1080，24 fps |
| 人物高 | 约 40 px（占画面高 18 %） | 48–64 px（27–36 %） |
| 地面 / 对话区 | 可走纵深带默认 y 158–198（各地图 160–204 不等）；对话框盖 y ≥ 170 | `GROUND = 150`；对话框盖 y ≥ 136 |
| 背景 | 已拆成视差图层导出 | 每个背景函数一次画满 320×180，463 行用到 `W/H` + 大量手调绝对坐标 |

整数倍放大能占多大（本次脚本算的，“占宽”= 画面宽 / 视口物理宽）：

| 视口 | 物理像素 | 384×216 | 占宽 | 320×180 | 占宽 | 只按 640×360 整数倍 | 占宽 |
|---|---|---|---|---|---|---|---|
| 1920×1080 全屏 F11 | 1920×1080 | 5× → 1920×1080 | 100% | 6× → 1920×1080 | 100% | 3× → 1920×1080 | 100% |
| 1920×1080 屏 Chrome 最大化 | 1920×969 | 4× → 1536×864 | 80% | 5× → 1600×900 | 83% | 2× → 1280×720 | 67% |
| 1920×1080 笔记本 125 % | 1920×912 | 4× → 1536×864 | 80% | 5× → 1600×900 | 83% | 2× → 1280×720 | 67% |
| 1920×1080 笔记本 150 % | 1920×878 | 4× → 1536×864 | 80% | 4× → 1280×720 | 67% | 2× → 1280×720 | 67% |
| 1366×768 笔记本最大化 | 1366×657 | 3× → 1152×648 | 84% | 3× → 960×540 | 70% | 1× → 640×360 | 47% |
| 2560×1440 最大化 | 2560×1305 | 6× → 2304×1296 | 90% | 7× → 2240×1260 | 88% | 3× → 1920×1080 | 75% |
| iPhone 14 横屏 | 2532×1170 | 5× → 1920×1080 | 76% | 6× → 1920×1080 | 76% | 3× → 1920×1080 | 76% |
| 安卓 915×412 横屏 | 2402×1082 | 5× → 1920×1080 | 80% | 6× → 1920×1080 | 80% | 3× → 1920×1080 | 80% |
| iPad 1024×768 | 2048×1536 | 5× → 1920×1080 | 94% | 6× → 1920×1080 | 94% | 3× → 1920×1080 | 94% |

结论：320 和 384 在大多数视口差不多（手机一样；1080p 最大化 320 略好；150 % 缩放和 1366 笔记本 384 好）；**“只按 640×360 整数倍”明显吃亏**（1080p 最大化只剩 67 %），所以 UI 层不能要求整数倍，只能跟着世界层的 s 走、按 s/2 放大。

### 10.2 方案 A：照搬 384×216

- 利：`ui.js / main.js / touch.js / world.js` 的坐标、字号、版式全部原样能用，改动最小；字库 12 / 16 px 直接用；银魂的测试脚本坐标能复用。
- 弊：
  - JoJo 背景是按 320×180 手调的整幅画，换成 384×216 要么把 `engine.core.W/H` 打补丁重渲（地平线、建筑、太阳这些绝对坐标会错位，等于重画），要么 1.2 倍非整数缩放（像素画糊掉、粗细不均），要么左右各补 32 px、上下补 18 px（得逐张补画）；
  - 分镜表（`剧情分镜\分镜总表.md`）和原片特效函数里的坐标（`speedlines` 默认中心 `W/2, H/2`、`GROUND = 150`、对话区 y ≥ 136）全按 320×180，搬过来每处要换算；
  - 人物相对画面变小（52 px / 216 = 24 %，原片 29 %），原片的构图和“打击感”的冲击力弱一点；
  - 文字和像素同一层，正文只能 12 px，每页 2 行 × 约 26 字，比原片少（原片 3 行 × 约 30 字）。

### 10.3 方案 B（建议）：世界 320×180 + UI 640×360

- 利：
  - 背景、人物、特效、分镜坐标全部 1:1 用 JoJo 原片的；`fx.py / text.py` 的 Python 版可以逐行翻成 JS，数值不用换算；
  - UI 层就是 JoJo 原片的 UI 层：对话框 / 旁白 / 地点卡 / 替身卡 / ゴゴゴ / 拟声字的版式直接照 `text.py`（§6.3），预渲染的卡片 PNG 1:1 贴；
  - 正文 16 px 点阵字、每页 3 行，字比像素细一半，是 JoJo 原片的观感；HUD（血条、替身能量、连击数、伤害数字）有更细的空间。
- 弊：
  - `ui.js / main.js / touch.js` 的所有坐标要重写（大致 ×5/3，并换成 JoJo 版式），`hint` 的换行宽、`tapRow`、`choiceLayout / menuLayout` 的点选几何都要跟着改；
  - 世界坐标里画的字（表情 `emote`、互动提示「▼ 调查」、敌人小血条、`G.fx.text`、`G.fx.word`）要挪到 UI 层画：`uiX = ((wx − camX) − zx0)·k·2`，`zx0 / k` 是推镜头的窗口左边和倍数（不推镜头时 `zx0 = 0, k = 1`），否则字会跟着世界变成 2 倍粗；
  - 屏幕倍数 s 为奇数时（1080p 最大化 s = 5 最常见），UI 层是 2.5 倍，16 px 宋体的笔画 2 / 3 像素交替。本次在 scratchpad 渲了对比图（`C:\Users\yui\AppData\Local\Temp\claude\D----\dd592801-8a86-495b-83a0-71d863169d18\scratchpad\understand\font_scale_test.png`：上 = 12 px × 5，中 = 16 px × 2.5，下 = 16 px × 2），能看出来但不影响阅读，可以接受；
  - s = 1（物理宽 < 640）时 UI 只有 0.5 倍看不清：强制 `s ≥ 2`，放不下就让 CSS 缩小（会糊一点，只在极小窗口出现）。

### 10.4 方案 B 的合成写法（给实现参考）

```js
// core.js（JoJo 版）
G.W = 320; G.H = 180;                    // 世界层
G.UW = 640; G.UH = 360;                  // UI 层
G.view = canvas(320, 180); G.g  = G.view.getContext('2d');
G.uiView = canvas(640, 360); G.ug = G.uiView.getContext('2d');
G.resize = () => {
  const dpr = devicePixelRatio || 1;
  const s = Math.max(2, Math.floor(Math.min(innerWidth * dpr / G.W, innerHeight * dpr / G.H)));
  G.scale = s; screen.width = G.W * s; screen.height = G.H * s;
  screen.style.width = G.W * s / dpr + 'px'; screen.style.height = G.H * s / dpr + 'px';
};
G.toGame = (e) => ({ x: (e.clientX - r.left) * G.W / r.width,  y: (e.clientY - r.top) * G.H / r.height });
G.toUI   = (e) => ({ x: (e.clientX - r.left) * G.UW / r.width, y: (e.clientY - r.top) * G.UH / r.height });

function render() {
  // 1. 世界层：背景、角色、世界特效、全屏特写的像素画部分；白闪只罩世界（照 JoJo fr.flash）
  resetCtx(G.g); G.g.fillRect(0, 0, 320, 180);
  G.scene.drawWorld(G.g);
  if (G.flashAlpha > 0) { … G.g.fillRect(0, 0, 320, 180) }
  // 2. UI 层：透明底；对话、HUD、名牌、拟声字、头顶字……然后黑幕，再画菜单 / 黑场旁白
  G.ug.clearRect(0, 0, 640, 360);
  G.scene.drawUI(G.ug);
  if (G.fadeAlpha > 0) { G.ug.globalAlpha = G.fadeAlpha; G.ug.fillRect(0, 0, 640, 360); G.ug.globalAlpha = 1; }   // UI 层整片黑 = 把下面的世界也盖住
  G.ui.drawTop(G.ug);
  // 3. 合成：冲击帧 / 时停滤镜只作用于世界层（JoJo fx.impact_frame 是改底层像素）
  sctx.imageSmoothingEnabled = false;
  sctx.filter = G.impactT > 0 ? 'grayscale(1) contrast(12) invert(1)' : (G.screenFilter || 'none');
  sctx.drawImage(G.view, 0, 0, screen.width, screen.height);       // s 倍，整数
  sctx.filter = 'none';
  sctx.drawImage(G.uiView, 0, 0, screen.width, screen.height);     // s/2 倍
}
```

另一个可选的折中（方案 B'）：世界 320×180，UI 也画在 320×180 上、正文 12 px（就是银魂版的做法，只把坐标 ×5/6）。改动比 B 少（不用拆两层、头顶字不用挪），任何倍数都清晰；代价是每页只有 2 行 × 约 21 字（对话框宽约 310、正文区约 254 px），和 JoJo 原片的观感不同，`text.py` 的版式不能直接照搬。若实现时间紧，B' 可以先上、以后再升 B。

## 12. 银魂版已知的坑（搬的时候别再踩）

- 每个中文字符串改动后要重跑 `font data`，否则缺字（`流程复盘.md:230, 499`）。
- 篇章卡 / 名牌图片缺失时画坏图会抛错让循环停住，现在 `ui.js:176, 201` 都先 `G.ready()` 再画（`流程复盘.md:397`）。
- 前一章结尾留下的全屏特写 / 白屏会盖住下一章，章节开头要 `S.insert(null)`（`流程复盘.md:395`）。
- 播放视频前要把黑幕清零（`script.js:458`）。
- 逐像素 `fillRect` 画线在没有显卡加速的浏览器里会卡到 1 帧 / 秒，横竖线一次 `fillRect` 画完（`流程复盘.md:454`）。JoJo 的特效（欧拉拳残影、集中线）粒子多，要注意每帧绘制次数。
- 调查点半径太大会盖住 NPC，“最近的那个”总是调查点（`流程复盘.md:396`）。
- 输了重来时 `actor:` 指定的敌人要复用同一个对象（`script.js:335-348` 的 `e._obj`）。
- 冲击帧依赖 canvas `filter`；旧版 Safari 对 `CanvasRenderingContext2D.filter` 的支持要实测，不支持时冲击帧 / 时停滤镜会静默失效（银魂的 iOS 也没真机测过）。
