## 0. 结论先说（给赶时间的人）

1. 银魂引擎很小、很干净：一个全局 `G`，固定 60 Hz 逻辑，单画布低分辨率整数倍放大；`G.world`（地图 + 角色 + 战斗）、`G.ui`（对话 / HUD / QTE）、`G.S`（`await` 式剧情 API）三块。**整体结构可以原样拿来**，剧情写法（`await S.say / S.walk / S.fight`）不用变。
2. 战斗是“清版动作”式：x 横向 + y 纵深（地面上的前后，约 40 px 宽的带子）+ z 高度；判定只用**点到点距离 + 前方区间**，没有身体宽度、没有 hitbox 矩形。
3. 玩家：J 三连击（8 / 8 / 14 伤害，按键缓冲接招）、K 跳 + 空中斩、按住 L 正面格挡；被打后 0.55 s 无敌；100 血，每场战斗开始回满。
4. 敌人：同时最多 2 个出手（“token”），出手前头顶 `!` 预警 0.32–0.5 s；Boss 会闪红光冲锋；被打会被打断（**任何敌人都没有霸体**）；KO 后打飞成天边的星星（银魂梗，JoJo 要换掉）。
5. `S.fight` 已经支持：波次、同伴、护送、剧情事件（打到一半演一段）、喊停条件 `endWhen`、计时、增援、只能撑时间、伤害倍率 `dmgMul`、打不死 `minHp`、指定落点击飞 `koTo`。**Boss 多阶段在银魂里是“多场 S.fight 串起来 + 中间演过场”或“events 里改参数”两种写法**。
6. JoJo 要加的东西大多能“挂”在现有结构上：替身 = 跟着本体的特殊 Actor；J 连打 = 按键时间窗计数；K = 新状态 `dodge`；L = 现有 `guard` 换皮 + 完美格挡；U = 新状态 + 能量条；换队长 = 不再用 `S.setPlayer`（会新建角色、丢血量），改成“队伍里已有的 Actor 互换 team 和 `W.player` 指针”。
7. **最大的坑是素材，不是代码**：JoJo 主角团图集几乎没有战斗帧（承太郎只有 idle / walk / run / sit / point / pose / shock / hurt），替身也只有 1–3 个动作（只有白金之星有 punch / rush / block），而银魂引擎默认每个角色都有 `attack / slash_up / thrust / hit / fly / guard / jump / ready / lie`。缺的动作名会**静默退回 idle**（`gfx.js` 107–113 行），看起来像“没反应”。必须先加一层动作名映射，并列出要补画的帧。
8. 引擎里有一个会直接伤到“连按出连打”的老毛病：**命中顿帧期间按的键会被丢掉**（`core.js` 210 行 `G.input.endStep()`），连打每下都顿帧的话会吞掉一半按键。改法见 §18.1。
9. 原工程画布 320×180（UI 层 640×360），银魂游戏是 384×216。JoJo 背景是按 320×180 画的，建议 `G.W/G.H` 改 320×180，UI 里写死的坐标要跟着改（清单见 §18.0）。这件事要总负责人拍板。

## 2. 游戏循环（`core.js`）

- 常量：`G.W = 384, G.H = 216`（5–6 行）。`G.time`（游戏时间，菜单打开时不走）、`G.realTime`、`G.hitStop`、`G.fadeAlpha`、`G.flashAlpha / flashColor`、`G.shakeT / shakeMag`、`G.impactT`（冲击帧剩余秒数）、`G.screenFilter`（整屏 CSS 滤镜字符串）（7–17 行）。
- 主循环 `frame(now)`（241–251 行）：`dt = min(0.1, 实际间隔)`，累加器 `acc`，**每步 1/60 s，一帧最多补 6 步**，补满 6 步就丢掉剩余（防螺旋）。`G.suspended`（手机竖屏）时只画不跑。
- 一步 `update(dt)`（205–219 行）顺序：
  1. `G.realTime += dt`；`G.audio.update`（音量渐变）；`G.ui.updateGlobal`（如果有）。
  2. `G.impactT -= dt`。
  3. **`if (G.hitStop > 0) { G.hitStop -= dt; G.input.endStep(); return; }`** ← 顿帧：整个场景（世界 + UI + 计时器）停住，**这几帧里按下的键被清掉**。
  4. `G.scene.update(dt)`（游戏中 = `G.worldScene`：菜单开着只更新菜单；按 Esc 开暂停；否则 `G.world.update(dt)` + `G.ui.update(dt)`，`main.js` 48–58 行）。
  5. 场景没冻结（没开菜单）时：`G.time += dt`；震屏计时；`G.timers`（`G.wait` 的 Promise）倒计时。
  6. `G.waiters`（`G.until(fn)`）每步检查一次条件。
  7. `G.input.endStep()` 清掉“这一步刚按下”的记录。
- 绘制 `render()`（220–240 行）：清黑 → `G.scene.draw(g)`（世界 + UI）→ 白闪 `flashAlpha` → 黑幕 `fadeAlpha` → `G.ui.drawTop`（黑幕之上的旁白、菜单）→ 把 384×216 的 `G.view` 最近邻放大画到屏幕画布；**冲击帧 / 整屏滤镜是在这一步给 `G.sctx.filter` 设 CSS 滤镜**：冲击帧 = `'grayscale(1) contrast(12) invert(1)'`，否则 `G.screenFilter`（比如回忆 `'sepia(0.85)'`）。注意它作用于**整张画面，包括 UI**。
- 画布缩放 `G.resize()`（73–82 行）：`s = floor(min(innerW·dpr / W, innerH·dpr / H))`，整数倍。
- 计时 / 等待：`G.wait(sec)`、`G.until(fn)`（193–194 行）；`G.shake(mag, dur)` 取最大值叠加（195 行）；`G.fade(to, dur)` / `G.flash(dur, peak, color)`（255–267 行，靠 `G.waiters` 每步推进，按 1/60 计时）。
- 场景切换 `G.setScene(s)`（199 行）；`G.runId`（`main.js`）每回标题 +1，正在跑的剧情发现 `runId` 变了就悄悄结束（`script.js` 17–19 行）。

## 3. 输入（`core.js` 93–126 行）

```
KEYMAP（94–100 行）
  ← → ↑ ↓ / A D W S        → left right up down
  J / Z                    → attack
  K / X                    → jump
  L / C                    → guard
  Enter / NumpadEnter / Space / E → ok
  Esc / P                  → pause
  Backspace                → back
```

- `G.input.down[a]`（按住）、`G.input.hits[a]`（这一步刚按下；keydown 时 `!down[a]` 才记，所以系统按键重复不算），`isDown(a) / hit(a) / consume(a)`，`okHit()` = `ok || attack`（**J 也能推进对话、确认菜单**），`consumeOk()`，`endStep()` 清 `hits` 和 `tap`。
- 失焦 `blur` 清空 `down`（125 行）。画布 `pointerdown` = 一次 `ok` + 记 `tap` 坐标（126 行，菜单靠它判断点中哪一项）。
- 触屏：`touch.js` 把按钮写进同一套 `down / hits`（27–30 行 `setKey`），按钮在 `index.html` 112–115 行，`data-key` 就是动作名；`touch.js` 34–37 行收集按钮、41 行挂事件。**加 U / 换人键 = 在 index.html 加两个 `.tc-btn`、在 touch.js 这两处加上**。
- 没有“按键时间戳”，也没有输入缓冲队列；连按判断只能在逻辑里自己记。

### 4.2 动画

- `play(name, {restart, speed})`（64–67 行）：换动作时 `animT = 0`、清定格；`speed` = 播放倍率。
- `frameIndex()`（74–79 行）：`n = floor(animT · fps · animSpeed)`，loop 取模，其他停在最后一帧；`frozen` 优先。
- `animDone()`（80 行）：非 loop 且播完一遍。**static（单帧）动作也会“播完”**：1 帧 / fps 秒后算完。
- `get a()`（73 行）→ `atlasFor(anim).anim(anim)`；`Atlas.anim(name)`（`gfx.js` 107–113 行）：**找不到动作名就退回 `aliases` → `idle` → 第一个动作，不报错**。
- 时间都是按秒推进（`world.update` 658–659 行每帧 `animT += dt; stateT += dt`），和图集 fps 无关，所以 JoJo 2 fps 的 idle 也能正常播。

### 4.3 绘制 `draw(g, camX, camY)`（82–111 行）

影子（`12·scale` 宽、2 px 高的半透明黑条，死了 / 有旋转时不画）→ 载具 `ride`（坐骑帧、座位抬高、前景、车灯相加混合）→ `Atlas.draw(g, anim, frame, x, y - z, {flip, scale, alpha, flash, rot, tint})`。`Atlas.draw`（`gfx.js` 145–173 行）：平移到脚点、旋转、缩放 / 翻转、画格子，再按需叠 `tintImg(color)`（染色）和 `whiteImg()`（白闪）。玩家 / 同伴无敌时每 1/20 s 闪一下（`alpha 0.45`，90 行）。

## 6. 纵深排序、镜头、推近

- **排序**（`drawScene` 773–783 行）：道具（`depth ?? y`）、角色（`y`，**死了的 +1000 永远在最上**）、飞行道具（`y + 0.5`）放一个数组按 y 排，从小到大画。然后背景前景层 `bg.drawFg`、世界坐标特效 `G.fx.draw(..., false)`、头顶符号 / 敌人小血条 / 互动提示，最后屏幕坐标特效 `G.fx.draw(g, 0, 0, true)`（集中线、星星）。
- **震屏**：`drawScene` 764 行，每帧随机偏移 `±shakeMag`（y 方向 ×0.6），整数像素。
- **镜头** `updateCamera`（733–743 行）：目标 = `focus‖player` 的 `x - W/2 + facing·18`（玩家朝向前瞻 18 px）；`st.camTarget`（数字）优先；夹在锁定区 / 地图范围；`camX += (目标 - camX)·min(1, dt·5)` 指数跟随。`snapCamera()` 直接到位。`camY` 一直是 0（没有纵向镜头）。
- **推近** `W.zoom = {k, x, y}`（`draw` 747–759 行）：整个场景先画到 `W.zbuf`（同尺寸离屏画布），再取中心区域放大贴回。**时停滤镜可以照这个“先画到缓冲再处理”的路子做**（§18.10）。

## 7. 互动 / 触发区 / 剧情锁

- `W.update` 683–713 行：只有 `W.free && !S.busy && !W.combat && 玩家没倒地` 时才检查。
  1. 触发区：玩家脚点 x 在 `[x0, x1]`（有 y0/y1 再查 y）且 `cond()` 为真 → `fired = true`（`once !== false`）→ `G.S.run(tr.run)`，一帧只触发一个。
  2. 互动：`findNear()`（717–731 行）找最近的可搭话角色（`dx < 26`、`dy < talkRy`）或调查点（`dx < r`、`dy < ry`），评分 `dx + 1.5·dy`；按 ok 键 → 角色：双方转向、`S.talker = a`、`await a.talk(S, a)`；调查点：`G.S.run(h.use)`。
  3. 头顶画 `▼ 标签` 提示框（795–803 行）。

### 9.2 `hitCheck(att, spec)`（235–247 行）

对地图上每个角色 `t`：跳过自己、已移除、已死、`npc`、同阵营、这招已打中过、`t.invuln > 0`、`t.state === 'down'`；然后

- `dx = (t.x − att.x)·att.facing` 在 `[reach[0]·sc − 3, reach[1]·sc + 3]`（`sc` = 攻击者体型）；
- `|t.y − att.y| ≤ 8·max(sc, t.scale)`（纵深容差 8 px）；
- `|t.z − att.z| ≤ 26`（高度差）。

通过就记进 `hitList` 并 `hit(att, t, spec)`。**没有身体宽度**：大个子敌人身体前沿比脚点远，打起来会觉得“够不着”；JoJo 敌人体型差别大（伊奇 26 px 宽、法皇 75 px 宽），建议加 `t.bodyW`（§18.3）。

### 9.3 `hit(att, t, spec)`（248–283 行）流水

1. **格挡**：`t.state === 'guard'` 且攻击者在 `t` 面朝的一侧（`sign(att.x − t.x) === t.facing`）→ 不掉血，`clang` + 浅蓝火花 5 颗，`t.vx = att.facing·70`，`G.hitStop = 0.04`，结束。
2. **伤害倍率** `t.dmgMul(t)`：≤ 0.01 → 免疫：`clang` + 紫色火花 + 40% 概率飘字“……没用”，顿帧 0.03，结束。
3. 掉血 `max(1, round(dmg·mul))`；`minHp` 托底；白闪 `flash = 1`。
4. 无敌：玩家 0.55 s、同伴 0.4 s、**敌人 0**（敌人靠 `hitList` 防一招多中，所以连段能接上）。
5. 顿帧 `G.hitStop` = 重击 0.09 / 普通 0.05 s；震屏 3 / 1.5 px、0.15 s；音效 `spec.sfx` + 受击音（打玩家是 `punch`，打别人是 `hit`）；暖白火花 7 颗 + 光圈；重击或 15% 概率出拟声字（砰 / 咚 / 唰）。
6. 血 ≤ 0 → `ko(t, att)`。
7. 否则 `state = 'hurt'`、**取消正在出的招（`t.atk = null`）**、播 `hit`（2.4 倍速）、`vx = att.facing·kb`、转身面向攻击者；敌人 `cool ≥ 0.5`。

### 9.4 `ko(t, att)`（284–305 行）

- 敌人：`dead = true, state 'dead'`，播 `fly`，`vx = 130`（Boss 90）、`vz = 240`（Boss 170）——**没有重力，一直往上飞**；屏幕上 `y − z < −30` 或飞了 2.5 s 就移除，并在天边画一颗闪烁的星星 + `twinkle` 音效（580 行）。Boss 额外：顿帧 0.3、震屏 4 / 0.5 s、白闪 0.3 @0.8、拟声“咔嚓!”。`koImpact`：3 帧冲击帧 + 集中线 + “砰!!”。`koTo = {x, y, z, dur=0.42, arc=26}`：沿抛物线飞到指定落点（打穿墙），落点执行 `onKo(e)`（565–576 行）。
- 玩家 / 同伴：`state 'down'`，播 `hit` 再 `lie`，`vx = 90`，`thud`。

### 9.5 防御的完整规则

- 只有战斗中、站着（idle / walk）按住 L 才进格挡；格挡挡**正面**的近战和飞行道具（`updateShots` 353–356 行），爆炸也走 `hit()` 的格挡判定（攻击点算在爆心外侧，正面就能挡）。
- 没有防御耐久、没有破防、没有完美格挡、没有反击。

### 16.6 战斗 `S.fight(spec)`（`script.js` 264–422 行）

**spec 字段**

| 字段 | 说明 |
|---|---|
| `arena: [x0, x1]` | 锁定场地（镜头和移动都限制在里面；常用 `[cx, cx + G.W]` 或 `[camX + 8, camX + 376]`） |
| `waves: [[敌人, …], …]` | 一波打完（`enemies()` 为空）才出下一波 |
| `allies: [id…]`, `allyHp` | 战斗时改成 `team 'ally'`，打完改回 `'npc'`（跟随关系保留） |
| `vip`, `vipHp` | 护送目标（不出手，倒下算输） |

| `after` | 打完放的曲子；默认恢复战前；`null` = 不换 |
| `events: [{when(t), run: async (S, enemies, attempt)}]` | `t` = 本场已打秒数；满足就停手（敌人回 idle）演一段再继续；每次重来重置 |
| `endWhen()` | 剧情喊停，成立算赢，剩下的敌人原地站着交给后面的剧情 |
| `timer: {label, until}` | 右上倒计时（只显示，结束要配 `endWhen`） |
| `survive: true` | 敌人清空也不算赢（配 `endWhen`） |

| `onWave: async (S, wi, spawned, attempt)` | 每波走进场后、开打前（常用来说台词、染色、挂附加图集；`attempt > 0` 时一般跳过台词） |

**敌人写法**：`{ cid, id, actor, name, hp=30, scale=1, boss, speed=46, range=25, ranged=0, noCharge, moves=['E_SLASH'], idle='idle', minHp, koTo, onKo, koImpact, dmgMul, side='right'|'left'（默认奇偶交替）, y }`。`actor` = 用地图上已有的角色当这个敌人（剧情里提前摆好的人），重来时**复用同一个对象**（`e._obj`，335–348 行，修过的坑）。增援的写法少一些：`{cid, id, name, hp=24, scale, speed=50, range, ranged, moves}`。

**流程**：
1. 锁场、换曲、开 HUD、记开场位置；同伴 / VIP 改阵营。
2. 每次尝试：玩家回满血、清状态；同伴回满、重来时摆回玩家身边；VIP 回原位；事件重置；`fightT = 0`；有增援就挂一个 tick。
3. 每一波：新敌人在场外（左 `x0 − 20 − k·14` / 右 `x1 + 20 + k·14`）生成，**`combat = false, free = false`，以 80 px/s 走进场**（到 `x0 + 34 + k·16` / `x1 − 34 − k·16`），全部转向玩家 → `onWave` → `combat = true, free = true` → 等：敌人清空 / 玩家（或 VIP）倒地 / `endWhen` / 某个事件触发。
4. 输：等 1.3 s → 移除所有敌人和子弹 → 菜单「再来一次 / 回到标题」（选回标题会 `G.goTitle()` 并返回一个永不 resolve 的 Promise）→ 黑幕 → 从第 2 步重来。
5. 赢：等 1.0 s（`endWhen` 喊停时 0.4 s）→ 解锁、关 HUD、清提示、玩家回满、同伴改回 `npc`、换曲。

注意：`S.fight` 开头把 `W.player` 存进局部变量 `p`（273 行），之后**全程用这个 `p`**（判输 366 行、重来复位 288 / 297 行等）；战斗中途换主角不会被识别——JoJo 要改（§18.9）。

**实际用法举例**：序章 `prologue.js` 99–113 行（两波杂兵 + 每波台词）、122–140 行（第二波是 Boss，`scale 1.45`）；第三章 150–167 行（同伴神乐远程助战 `k.ranged = 80; k.allyMoves = [G.MOVES.E_GUN]`，打完还原）；第十三章 462–466 行（四个同伴 `allyHp 110`、`onWave` 把奈落染暗）、704–708 行（玩家可选三人之一）。

## 17. 已知的坑 / 限制（和 JoJo 相关的）

1. **顿帧吞键**：`core.js` 210 行。顿帧中按下的 J 被 `endStep()` 清掉；普通命中 0.05 s = 3 步，Ora 连打期间约有一半按键会丢。
2. **全局顿帧冻结所有东西**（含 UI、计时器、其他敌人）：多人混战、连打高频命中时整场会一顿一顿的。
3. **缺动作静默退回 idle**（`gfx.js` 107–113 行）；`startAttack` 只在动作名不存在时退回 `'attack'`（216 行），JoJo 角色连 `attack` 都没有 → idle。
4. `hit()` 里受击动作写死 `'hit'`，倒地写死 `'hit' → 'lie'`，KO 写死 `'fly'`；`down` 状态靠 `p.anim === 'hit'` 判断该不该换 `lie`（467 行）——加动作名映射时要保留“逻辑名”，不然这些判断失效。
5. 多个同伴跟同一个人会叠在一起（§12）。
6. `S.fight` 里的 `p` 是开战时的主角（§16.6）。
7. `S.setPlayer` 新建角色，不继承血、能量、附加图集（第十三章每次都要 `gear()` 重挂附加图集）。
8. 敌人没有霸体，Boss 三连就能打断；没有招式顺序；预警只有 `!`。
9. 打飞成星星是银魂梗（`ko` 288–290 行 + `updateEnemy` 577–582 行），JoJo 要换成“再起不能”式的击飞。
10. `G.screenFilter` / 冲击帧作用于整张画面（含 UI），不能做“世界变色、时停里能动的人保持彩色”。`ctx.filter` 在 iOS Safari 上的支持要实测（银魂的冲击帧在 iPhone 上可能本来就不显示）。
11. 音效用 HTMLAudio，同名最多 6 个并发、每次 `currentTime = 0` 重播：连打每秒 12 下“啪”会互相截断，要节流或做专门的连打循环音。
12. 背景只有横向镜头（`camY` 恒 0），没有纵向卷动。
13. `S.arc` 会把 `hold` 留成 true；`W.ticks` 不会随换图自动清，各章都用 `if (G.world.stage !== st) return true` 自己清。

### 18.8 队伍 / 自由走动时换队长（新文件 `engine\party.js`）

**为什么不用 `S.setPlayer`**：它每次 `new Actor`，旧的移除或改 id 当 NPC，血、能量、替身、附加图集全丢，还会改 id（剧情里拿着的引用失效）。JoJo 要“随时换”，必须**复用同一批 Actor，只换 `team` 和 `W.player` 指针**。

```js
G.party = {
  members: [],          // Actor 数组（队伍顺序），每人 id = 自己的 cid（'jotaro'、'kakyoin'…），永远不改
  lockLeader: false,    // 剧情锁定队长（单人章节、过场）
  trail: [],            // 队长走过的点（贪吃蛇式跟随用）
};
function setLeader(next, o = {}) {
  const W = G.world, old = W.player;
  if (!next || next === old || next.state === 'down' || G.party.lockLeader) return false;
  old.team = W.combat ? 'ally' : 'npc'; old.state = 'idle'; old.atk = null; old.focus = null; old.cool = 0.6;
  next.team = 'player'; next.follow = null; next.hold = false; next.state = 'idle';
  W.player = next; W.focus = null;            // 镜头会自己缓动过去（updateCamera 指数跟随）
  rebuildFollow();                             // 其余人重新排队
  G.fx.twinkle(next.x, next.headY() - 4, 6, next.standColor);  G.audio.sfx('pop', 0.6, 1.3);
  G.ui.leaderCard(next);                       // 左上角头像框换人的小动画
  return true;
}
```

- 键：`swap`（Q / Tab）= 下一个没倒地的队员；`lead1..6` = 直接选。只在 `W.free && !G.S.busy && !G.ui.blocking()` 时处理（`updatePlayer` 开头）。非战斗冷却 0.3 s，战斗中 1.0 s。
- **id 约定**：队员的 id 一直是自己的 cid。`S.actor('player')` 已经特判返回 `W.player`（`script.js` 25 行）；`S.say('jotaro', …)` 在 `stage.find('player')` 找不到时会退回 `W.player`（174–175 行），所以剧情代码不用改。
- **跟随**：把 `updateFollow`（474–493 行）改成“轨迹跟随”，解决多人叠一团：
  - 队长每移动 ≥ 2 px 就往 `party.trail` 头部塞一个点（最多 200 个）。
  - 第 i 个跟随者（i 从 1 开始）的目标 = `trail[i·11]`（约 22 px 一个人），纵深再交替加 `[−3, +3, −5, +5, 0]`；队长停下时大家停在各自的点上。
  - 速度、走 / 停阈值、220 px 瞬移沿用原值。
  - `rebuildFollow()`：换队长、换图、入队 / 离队时清空轨迹，按队伍顺序（旧队长排第一个）重设 `follow` 和 `followSlot`。
- `S.setStage`（`script.js` 253–262 行）：`carry` 自动加上 `G.party.members` 里除队长以外的所有人（`setStage` 里 `28 + i·20` 的初始排布保留），换图后 `rebuildFollow()`。
- 新 API：`S.party(['jotaro','kakyoin',…])`（设定当前队伍并生成角色）、`S.join(id)` / `S.leave(id)`（加入 / 离队，带 `S.notice` 提示）、`S.lead(id)`（剧情指定队长）、`S.lockLeader(bool)`。

### 18.10 时停框架（新文件 `engine\timestop.js`）
