## 0. 先看结论

1. **银魂 build_assets.py = 7 步**：`chars bg ui audio video font data`。每步把元数据写 `tools\_meta\<步>.json`，最后 `data` 步把这些 json 合成 `data.js`（`window.GAME_DATA = {...}`），所以每步能单独重跑。默认（不带参数）跑除 `video` 外的 6 步。
2. **背景不是整帧截图**：import 原 Python 工程，直接调它内部的“图层函数”（`C.sky`、`K._facade`、`C._stone_strip` …）把每层存 PNG，把视差系数 / 周期 / 位置写成图层字典，由游戏 `engine\gfx.js` 的 `Background.layer()`（216 行起）按原公式在 JS 里画；会动的小东西要么烘成循环帧（`frames`），要么在 JS 里重写（`clouds / lanterns / flags / reflect / rows …`）。
3. **playtest.py** 用 Playwright 无头 Chromium，每 ~0.08 s `page.evaluate(STATE_JS)` 读一次游戏状态（`G.world / G.ui / G.S / G.flags / G.dbg …`），用键盘事件推对话、走位、打架；每章一个 `route_chN()`。**JoJo 引擎只要原样暴露第 3.2 节那张表里的字段，playtest 就能大部分照搬。**
4. **JoJo 原工程和银魂原工程接口不同，build 不能照抄**：
   - 画布 320×180 + UI 层 640×360（银魂是 384×216 单层）；
   - **没有预烘的音频**（银魂有 `音频\` 目录的成品 wav），要现场调 `engine.music.track()` / `engine.sfx.make()` 合成——实测 10 首配乐共 22 s、64 个音效共 2 s，很快；
   - 场景渲染走 `源码\tools\common.py` 的 `load_scene / render_frame` + `Frame.compose()`，混音走 `源码\tools\render.py` 的 `build_audio()`；音效事件只有逐帧渲染时才收集得到，所以**视频要先渲画面再混音**；
   - 背景是 33 个 `name(fr, scroll=0.0, **kw) -> info` 函数，静态部分都在 `@functools.lru_cache` 的 `_xxx_static() / _xxx_layers()` 里，可以直接拿来存图层。
5. **建议 JoJo 游戏用 640×360 逻辑画布、两层画**：世界画到 320×180 离屏画布、×2 最近邻贴上，UI / 文字直接画在 640×360 上（等于原工程 `Frame.compose()`，core.py 262–298 行）。理由：JoJo 所有文字、名牌、替身卡、logo 都是按 640×360 UI 层做的（宋体 12/16 px、微软雅黑粗体 26 px），缩回 320×180 字会看不清；录屏 640×360 ×3 正好 1920×1080。**这一条要总负责人拍板**，下面 font / ui / video 的设计都按它写。

### 2.7 `video`（664–695）

1. 银魂入口：`engine.render.load_scene("s00")` 返回场景对象；`render_frame(sc, t)` 返回 384×216 RGB；`engine.audio.build_mix([sc], wav)` 整场混音；`FPS` = 30。
2. `VIDEO_CUTS = [("s00a", 0.0, 8.2), ("s00b", 8.2, None)]`。
3. 每段起一个 ffmpeg：
   - 视频从 stdin 读 `rawvideo rgb24 (W*2)x(H*2) @FPS`；
   - 音频是第二输入 `-ss a -t (b-a) -i wav`；
   - 编码 `libx264 -preset slow -crf 16 -pix_fmt yuv420p -tune animation`，`aac 160k`，`+faststart`，`-shortest`；
   - 逐帧写 `render_frame(...).resize((W*2, H*2), NEAREST)`。
4. 再转 webm：`libvpx-vp9 -crf 30 -b:v 0 -deadline good -cpu-used 4 -row-mt 1` + `libopus 128k`。
5. meta：`{name: {src, webm, duration}}`；删临时 wav。
6. **Playwright 自带的 Chromium 不带 H.264**，所以必须另出 webm；游戏里能放 webm 就优先 webm。

### 2.8 `font`（699–736）

- `collect_text()`：
  - 扫 `story\*.js`、`engine\*.js`、`main.js` 里所有引号串（正则 ``(['\"`])((?:\\.|(?!\1).)*)\1``，**只认单行**）；

  - 加全角空格（`isprintable()` 会把它滤掉，所以显式加）。
- `build_font()`，对 12 px 和 16 px 各做一张：
  - `ImageFont.truetype("C:/Windows/Fonts/simsun.ttc", size)`；
  - `asc, desc = getmetrics()`，`lh = asc + desc`；
  - 64 列，格宽 `size + 1`，行高 `lh + 1`；
  - `d.fontmode = "1"`（不抗锯齿），`d.text((x, y + asc), ch, anchor="ls")` 白字；

## 3. playtest.py：怎么驱动游戏自动通关

### 3.1 启动（`run()`，807–882）

- **地址**：
  - 平时 `file:///…/index.html`；
  - 录屏时起 `ThreadingTCPServer(("127.0.0.1", 0))`，用 http 打开（`file://` 下画布和音频算跨域，`captureStream` / WebAudio 录不出来）。
- **浏览器**：`pw.chromium.launch(args=["--autoplay-policy=no-user-gesture-required"])`。viewport 平时 1152×648（= 384×216 ×3），录屏时 384×216 原尺寸。
- **收报错**：`page.on("console")` 收 error / warning，`page.on("pageerror")`。录屏时 `page.expose_function("__recSave", …)` 让页面把 webm 数据块交给 Python 写盘。
- **等就绪**：`page.wait_for_function("() => window.G && G.scene && G.f12", timeout=60000)`。字库对象建好了 = 标题出来了；再 sleep 1 s。
- **选章**：
  - `all` / `prologue` → `route_prologue`；
  - `ch1` → `pick_chapter(1)`；
  - `ORDER` 里的章 → `pick_chapter(2 + start)`；
  - 之后按 `ORDER` 一路打下去（游戏本身也会接下一章）；遇到 `until` 或 `scene == "end"` 停。
- **输出**：
  - stdout 打一个 JSON：`{errors[:40], shots, notes, dialog_lines, trace, marks, final}`。`notes` 是 log 里不以 `.png` 结尾的条目：`advance_timeout:{状态}`、`fight_timeout:`、`npc_missing:`、`npc_not_near:`、`explore_talk:`、`explore_walk:`；
  - 录屏时同样内容写 `run.json`；
  - `dialog_seen.txt`：见过的每句台词；
  - 截图目录 = 环境变量 `PLAYTEST_OUT` 或 `tools\_playtest\`，文件名 `NN_名字.png`。
- **参数**：`which`（`prologue|ch1|ch2…|all`）、`--lose`、`--until 章`、`--record 目录`。

### 3.3 Tester 的动作（71–451）

- `st()`（91）：读一次状态，顺便记三样：
  - 换图时间 `trace`（`"%6.1fs stage"`）；
  - 篇章卡 / 过场 / 全剧终 / 战斗开始结束 → `marks [秒, 名, 类型]`（录屏剪辑用）。
- `chap_changed()`（111）：地图的章号变了（不等于 `self.chap`）就立即结束当前步骤，防止一路空等到下一章。
- `advance(timeout, stop, choose, shots)`（219–272）：主循环，每 0.08 s 一轮：
  1. 先看 `stop(s)`、`chap_changed`；
  2. `special(s)`：`waitKey` → 按 Enter；`qte` 连按 / 看准时机（`zone[0]+0.02 ≤ m ≤ zone[1]-0.02` 才按）/ 节拍（`|t - note| < 0.07`）；`runner` 障碍 `6 < dx < 36` 且在地上就按 `k`；
  3. 新台词进 `lines`；台词里含 `shots` 字典的键就截图（`{台词子串: 截图名}`）；
  4. 菜单 → Enter；选项 → `choose(options)` 返回按几下 ↓；对话 / 旁白 / 系统框 → `can_skip` 后 Enter；
  5. `scene == world && free && !busy` 且没给 `stop` → 返回；`scene == end` → 返回；
  6. 给了 `stop` 但玩家闲着超过 5 s（录屏 7 s）→ `explore()`：先找最近的没聊过的 NPC 聊，聊完往右走 150 px、走到头折回。
  - 超时记 `advance_timeout`。
- `walk_to(x, y, timeout)`（295）：按住方向键直到误差 ≤ 3 px；游戏一忙（`!free || busy`）或换章立即松键返回。**所以剧情打断走路后，后面的 `advance(stop=开打)` 可能空等**（银魂复盘十四节的坑）。
- `use(x, y, label)`（316）：走到点，等头顶提示是这个 `label` 再按 Enter，然后 `advance`。
- `use_npc(label)`（412）：从 `npcs` 读实时位置，依次试 dx = −18 / −8 / +8 / −18 贴近再搭话。
- `fight(timeout, shot_name, shots, choose)`（330–410）：
  - 每轮先处理菜单（输了 → 截 `lost_menu` → Enter 选“再来一次”）、选项（返回）、小游戏、对话；
  - 不在战斗且能动 → 返回；
  - `--lose` 时第一场站着不动等输；
  - 撑时间战（有 `timer`、只有 1 个敌人、hp ≥ 900）：面朝它按住 `l` 防御；
  - 否则：找曼哈顿距离最近的敌人；先对齐纵深（`|dy| > 3` 按 ↑↓ 0.06 s）；`|dx| > 26` 就走过去，否则转身连按 3 下 `j`。
- `pick_chapter(idx)`（440）：标题 ↓ Enter（“选择章节”）→ ↓ × idx → Enter。
- 录屏模式（`watch=True`）：
  - 所有超时 ×4（`tmul`）；
  - `can_skip` 等字打完，再按字数留读的时间（`min(3.6, 1.0 + 0.08 × 字数)`，系统框 2.4 s）；
  - `lingered` 让选项 / 菜单停 1.5–1.8 s 再按；
  - `idle()` 用 `page.evaluate("1")` 代替 sleep（让录像数据块及时写盘）；
  - 不截图。

### 3.4 `G.dbg` 钩子

- 剧情里写一行 `const mark = (name) => { G.dbg = { shot: name }; };`（chapter13.js 30 行、chapter14.js 27 行），在没有台词的镜头处调 `mark('ch13_xslash')`。
- STATE_JS 读 `G.dbg.shot`，`dbg_shot()` → `shot_once(name)`：每个名字只截一次，所以 `G.dbg` 不用清。

### 3.5 路线写法（454–800）

- 每章一个 `route_chN(T)`，都是这几种调用串起来：
  - `T.advance(stop=lambda s: s["stage"] == "xxx_chN" and s["free"] and not s["busy"], shots=shots)`
  - `T.use(x, y, "名")` / `T.use_npc("名")`
  - `T.walk_to(x, y)`
  - `T.advance(stop=lambda s: s["combat"])`
  - `T.fight(shot_name=…)`
- 章末都用：`T.advance(stop=lambda s: s["scene"] == "end" or s["stage"] not in (None, 本章各图…))`
- `ROUTES / ORDER`（803–804）登记。
- 例外：
  - 第六章（小游戏合集）整章就一句 `advance(timeout=200)`；
  - 终章用“往右走 → 处理剧情 → 没开打接着走”的循环（784–790），绕开 `walk_to` 被打断的坑。

### 3.6 限制

- 自动战斗只会贴近连按 J；“输了重来”只在序章测过（`--lose`）。
- 路线里的坐标是写死的，改了地图要跟着改。
- `advance_timeout` 多数是脚本自己在等不会来的事件——要看 `trace` 判断游戏有没有真卡住。

**`build_audio` 的混音规则**（tools\render.py 57–182）：

- 音乐：相邻场景同一 key 连续放，0.08 s 淡入、0.45 s 淡出。
- 音效：`fr.events` + `mod.SFX` 两个来源；`vol / pan` 由混音器处理。
- 合成：`mus * 0.62 * duck + fx * 0.85`，其中 `duck = 1 - 0.35 * clip(env * 2)`（大音效时压低音乐）。
- 响度：门限 RMS 归一到 −17 dBFS；软拐点限幅（knee 0.62 → ceil 0.8）；输出 int16 ×32000。
- 它只读 `mod.DURATION / MUSIC / MUSIC_VOL / SFX`。

**sfx.py 要点**：

- `make(name, **kw)` → float32，单声道 (N,) 或立体声 (N, 2)；
- `NAMES` 64 个；
- 通用参数 `dur / pitch / seed`；`HIT` = 主冲击点偏移（timestop 0.85 s、time_resume 1.02 s、sting_reveal 0.26 s …）；
- `_LA` 响度表已经平衡过各音效的响度；
- **依赖 scipy**（本机 1.16.3）。

**实测**（probe_bg / probe_video）：

- 33 个背景首次调用 3–43 ms（建缓存），之后 0–21 ms / 帧；
- s00 / s01 渲染 12 ms / 帧，s20 7 ms / 帧，`compose()` 输出 640×360。

**33 个背景的循环性**（probe_period：scroll=0，24 fps 渲 16 s；完整结果在 `probe_period.txt`）：

- **只有 `india_alley` 有 ≤ 12 s 的精确周期（10.00 s）**；
- `world_map` 只有 2 张不同的帧（`phase = int(t/0.6) % 2`）；
- 其余都有不循环的漂移（多个不可公度的频率）。会动像素的占比：
  - 很小：`desert(night)` 0.1%、`cairo_rooftops` 0.1%、`pyramids` 0.6%、`kujo_house(day)` 0.9%；
  - 很大：`sea_storm_night` 85%、`ship_hold` 67%、`dream_carnival` 58%、`sky_day` 48%、`underwater` 44%。

**图层宽度规则**（probe_layers）：

- `bg_asia` 的 `_wrap_paste(dst, src, off)`：**周期 = 图宽**（`_hk_layers()` 远 / 中 / 近都是 640 宽）；
- `bg_egypt` 的 `_scroll(dst, im, off, y)`：**图宽 = 周期 P + 320**（`_wrapped / _ext` 多接了一屏），`P = 图宽 − 320`。例：`_street_graded(time)` 1280 宽 → P = 960；`_street_ground` 800 → 480；`_desert_far` 960 → 640。

**特效能不能烘成透明帧**（probe_fx_matte）：

- 用银魂 `_matte` 的黑底 / 白底双画法反解透明度，再叠回一张真背景，和直接画在背景上逐像素比：
  - `hit_spark / shockwave / explosion / rush / emerald_splash`：**差 0**；
  - `fire_ankh`：最大差 1；
  - **相加光 `fx.glow(add=True)` 不行**（差 137）：要按 `lighter` 混合单独存黑底图，或在 JS 里用 `globalCompositeOperation = 'lighter'` 重画。

### 7.5 `fx`（可选，战斗特效预烘）

- 方法：`matte(lambda fr: fx.xxx(fr, x, y, t, t0, …))` 在 `t0 + k/24` 逐帧画 → 裁 bbox → 帧条，记锚点偏移。实测除相加光以外都和原画法逐像素一致。
- 适合预烘：
  - `hit_spark`（0.2 s）、`shockwave`（0.4 s）、`explosion`、`fire_ankh`（红色魔术师）；
  - `emerald_splash` 的单颗、`crack`、`glint`、`sparkles`；
  - `timestop`（ZA WARUDO）全屏滤镜不适合烘，JS 重写。
- `rush`（欧拉连打）是按 `[t0, t1]` 持续生成的拳影：烘一段 1–2 s 的循环。也可以烘 `starplat.fist / theworld.fist` 的拳影 + 速度线，在 JS 里按 `rate=30/s` 生成。
- 光环：
  - `sprite.aura` 简单（外扩 1 px 剪影 + ±1 px 抖动 + alpha 0.55）：build 时给每个替身图集烘一张同布局的“外扩剪影”图集，JS 用 `source-in` 染光环色，色从 `CARDS[i].aura` 取；
  - `fx.aura_flame` 用了噪声纹理，要么 JS 移植 `_noise_tex` / `_aura_fields`，要么按 12 fps 烘若干帧。
- 和负责特效调研的同事对一下边界（我只给方法和实测）。

### 7.7 `audio`（现场合成，不读 wav）

```python
from engine import music, sfx

def enc(x, path, br):                      # x: float32 (N,) 或 (N, 2)，44100 Hz；直接 pipe 给 ffmpeg，不落临时 wav
    ch = 1 if x.ndim == 1 else 2
    p = subprocess.Popen(["ffmpeg", "-y", "-loglevel", "error", "-f", "f32le", "-ar", "44100", "-ac", str(ch),
                          "-i", "-", "-c:a", "libmp3lame", "-b:a", br, path], stdin=subprocess.PIPE)
    p.stdin.write(np.ascontiguousarray(x, np.float32).tobytes()); p.stdin.close(); p.wait()

for k in music.TRACKS:                     # 10 首，共约 22 s
    enc(music.track(k), out("audio", "music", k + ".mp3"), "160k")
    meta["music"][k] = rel(...); meta["music_info"][k] = music.info(k)   # bpm / beat_sec / loop_sec：做卡点用
for key, (name, kw) in SFX_EXPORT.items():  # 64 个 + 变体，共约 2 s
    x = sfx.make(name, **kw)
    meta["sfx"][key] = dict(src=..., dur=round(len(x) / 44100, 3), hit=sfx.HIT.get(name))
for up in glob(assets\audio\user\*.mp3): meta["music"][文件名] = ...    # STAND PROUD 放这里，构建不覆盖
```

- **`SFX_EXPORT`**：64 个名字各出一份默认参数，外加变体：
  - `punch` / `punch_heavy` 的 `seed` 0–3（连打时轮换，不单调）；
  - `ora_rush` / `muda_rush` 出 `dur` 0.6 / 1.0 / 1.5 / 2.5 四档（它是渐强的，不能循环）；
  - 环境声 `wind / crowd / rumble / plane_engine / car_engine / heli / fire` 出 `dur` 6 s 循环用；
  - `menacing` / `dododo` 出 2 s、4 s；
  - 打字音只出 `blip`（30 ms），音高在 JS 里用 `playbackRate` 调（对应银魂的 `voice`）。
- **音量**：原片混音比例是音乐 0.62、音效 0.85，大音效时音乐压低 35%（第 6 节）。游戏的 `musicVol / sfxVol` 按这个比例设，可选做 ducking。
- **缓存**：没有源 wav 可比 mtime。用“输出存在就跳过、`--force` 重做”，或按 `music.py / sfx.py` 的 mtime 判断。

```python
from common import load_scene, render_frame, scene_frames    # 源码\tools\common.py
from render import build_audio                                # 源码\tools\render.py（只用这个函数）
VIDEO_CUTS = {"op": ["s00_opening"], "prologue": ["s01_coffin"], "ed": ["s20_farewell"]}   # 名字 → 场景（可多段连播）

for key, names in VIDEO_CUTS.items():
    p = Popen([ffmpeg, "-f", "rawvideo", "-pix_fmt", "rgb24", "-s", "1280x720", "-r", "24", "-i", "-",
               "-c:v", "libx264", "-preset", "slow", "-crf", "16", "-pix_fmt", "yuv420p", "-tune", "animation", tmp_mp4])
    scenes, start = [], 0.0
    for nm in names:
        nm, mod = load_scene(nm); n = scene_frames(mod); ev = set()
        for i in range(n):                                   # 必须逐帧渲染：音效事件只在画的时候登记
            fr = render_frame(mod, nm, i / FPS, i); ev.update(fr.events)
            p.stdin.write(fr.compose().resize((UW * 2, UH * 2), Image.NEAREST).tobytes())
        scenes.append((nm, mod, start, n, ev)); start += n / FPS
    p.stdin.close(); p.wait()
    build_audio(scenes, tmp_wav)                             # 原片同款混音、响度、限幅
    # 合流：-i tmp_mp4 -i tmp_wav -c:v copy -c:a aac -b:a 160k -movflags +faststart -shortest  → assets/video/<key>.mp4
    # webm：-c:v libvpx-vp9 -crf 30 -b:v 0 -deadline good -cpu-used 4 -row-mt 1 -c:a libopus -b:a 128k → <key>.webm
```

- **为什么输出 1280×720（UI 层 ×2）**：`compose()` 的 640×360 里 UI 文字有 1 px 细节，yuv420 色度减半会把文字描边的颜色抹开；×2 后每个 UI 像素都是 2×2，色度不丢。播放时 CSS `image-rendering: pixelated`。
- **耗时**：渲染 7–12 ms / 帧（s00 共 336 帧，约 4 s），时间主要花在编码上。
- **“虚拟场景”**：`render_frame` 只用 `mod.DURATION / render / FADE_IN / FADE_OUT`，`build_audio` 只用 `MUSIC / MUSIC_VOL / SFX` 和事件。所以 build 里可以用 `types.SimpleNamespace(DURATION=…, MUSIC="travel", render=fn)` 拼自己的过场：
  - 旅行地图一段：`bg.world_map` + `bg.draw_route(fr, ["东京", "香港"], t0=…, t1=…, vehicle="plane", day=1)`；
  - 替身登场特写、ZA WARUDO 等。

  照样走这条流水线，不碰 `源码\`。

### 7.9 `font`

- 尺寸：宋体 12 / 16 px，画在 640×360 UI 层，正好是 JoJo `tx.font("pixel", 12 / 16)` 的用法（对话 16、地名小字 12）。图集格式、JS `Font` 类照银魂。
- 扫字要比银魂多做三件：
  1. **多行模板字符串**：银魂的正则只认单行。直接收 js 文件里所有码点 > 127 的字符最稳，再加 ASCII 可打印字符；
  2. **数据里的字**：`角色图集\*.json` 的 `name`、`道具 / 场景专用` 的 `name`、`text.SPEAKERS`、`CARDS` 的 `cn / scn`、地名表……JS 拿 `G.D` 里的字符串去画时，这些字不在 js 文件里；
  3. **构建时查缺字**：渲染一个肯定没有的字（如 `\uFFFF`）当参照，位图一样的就是缺字，build 时直接打印（银魂只在运行时 `console.warn`）。宋体有假名（GB2312 收了平 / 片假名），ゴ / ド 能出。
- 可选：微软雅黑粗体（`msyhbd.ttc`，`fontmode="1"`）14 / 24 px 图集，给 HUD 上的替身名 / 大字动态排版用；固定文字还是在 `ui` 步预渲成图更省事。

### 7.10 `data`

- 合并 `_meta` 下 `chars / props / bg / fx / ui / audio / video / font` 写 `data.js`，格式 `window.GAME_DATA = …;`，同银魂。
- 再加 `heroes`（CARDS + SPEAKERS 合成的 6 人表）和 `music_info`。
- data 里任何**说明性字符串都不要以 `.png` 结尾**（会被预载）。

### 7.11 推荐的使用方式

```text
python tools\build_assets.py                       # chars props newchars bg fx ui audio font data（不含视频）
python tools\build_assets.py font data             # 改了台词
python tools\build_assets.py bg ui font data       # 改了布景 / 名牌登记表
python tools\build_assets.py video data            # 过场视频
set PYTHONDONTWRITEBYTECODE=1                      # 保险（脚本里也设了 sys.dont_write_bytecode）
```
